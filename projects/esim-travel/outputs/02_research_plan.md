# План исследования

Принцип: исследуем только то, что может изменить решение. Порядок — по цене ошибки.

Решение: запускать ли МегаФону travel-eSIM для россиян за рубежом (главная цель — удержание абонентов, выручка вторична, бюджет небольшой, горизонт год). Просматривающиеся варианты: **status quo** (не запускать), **свой продукт МегаФона** (на базе роуминг-активов, интеграция с абонентской базой), **партнёрство/агрегатор** (белый лейбл или альянс), **kill** (осознанно не входить — совпадает со status quo для нового продукта, отдельно не выделяем).

## Отброшенные вопросы
- Въездной сегмент (eSIM для иностранцев в РФ) — исключён брифом на C1.
- Ценообразование по странам и юнит-экономика конкретного тарифа — детальный продукт-дизайн, вне задачи; влияет на исполнение, а не на выбор «запускать/нет».
- Техническая реализация (SM-DP+, профильная инфраструктура) — не меняет выбор варианта; берётся на заметку в оценке сроков.
- Итоговое ценообразование/маркетинговая стратегия — шаг 6, если решение будет положительным.

## Заведомые пробелы
- Внутренние данные МегаФона (доля роумингового трафика, уходящего в агрегаторы; реальная выручка) недоступны по правилам среды. Закрывать позже: внутренним анализом компании или экспериментом из плана проверки (шаг 7).
