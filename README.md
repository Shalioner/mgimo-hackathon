# Стратег Фабрики продуктов

ИИ-агент для руководителя цифрового продукта: от размытого запроса до обоснованной продуктовой и коммуникационной стратегии. Агент сопровождает решение и после выбора.

> Не AI, который предлагает стратегию, а AI, который показывает, почему ей можно доверять и когда её нужно изменить.

Это **папка с инструкциями, знаниями и инструментами**, а не отдельная программа. Её открывают в Claude Code, Cursor, Codex или другой агентной среде.

## Быстрый старт (5 минут)

**Нужно:** Python 3.9+ и любая агентная среда с доступом к файлам и терминалу. Веб-поиск — встроенный в среду. Платных сервисов и ключей сверх подписки на саму среду не требуется.

```bash
git clone <ссылка на репозиторий> strategist && cd strategist
```

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
```

```bash
python tools/ledger.py status
```

Затем откройте папку в своей среде и напишите агенту задачу обычными словами, например:

> Почему у нашего сервиса X падает удержание и что с этим делать? Вот материалы: …

| Среда | Что агент читает автоматически |
|---|---|
| Claude Code | `CLAUDE.md` → `AGENTS.md`, навыки `.claude/skills/`, субагент `.claude/agents/claim-verifier.md` |
| Cursor | `.cursor/rules/strategist.mdc` → `AGENTS.md` |
| Codex, OpenCode и др. | `AGENTS.md` |

Агент сам создаст проект в `projects/<slug>/`, задаст несколько вопросов и пойдёт по шагам. Остановится он трижды, на ваших решениях:
- **C1** — подтвердить постановку задачи;
- **C2** — выбрать вариант;
- **C3** — утвердить пакет стратегий.

**Остановиться и продолжить:** просто закройте чат. В новом чате напишите «продолжи». Агент прочитает `projects/<slug>/state/progress.md` и продолжит с того же места.

**Исправить результат:** отредактируйте любой файл в `outputs/` или скажите агенту, что не так. Ваша версия главнее, агент перенесёт правку в реестр.

**Посмотреть пример:** `python tools/ledger.py impact projects/example CHG-001` показывает, какие выводы учебного кейса затронул новый опрос.

## Что агент выдаёт

`projects/<slug>/outputs/`:
- бриф (`01_brief.md`);
- план исследования (`02_research_plan.md`);
- картина ситуации «известно / откуда / не знаем» (`03_situation.md`);
- варианты с возражениями, включая «оставить как есть» и «закрыть» (`04_options.md`);
- продуктовая стратегия (`05_product_strategy.md`) и коммуникационная стратегия (`06_comms_strategy.md`);
- план проверки (`07_validation_plan.md`);
- журнал решений (`08_decision_log.md`);
- отчёт о времени и стоимости прогона (`09_run_report.md`).

У каждого существенного утверждения в тексте есть ID вида `[CLM-012]`. По ID в `state/ledger/` видно источник, цитату, тип (факт / прогноз / интерпретация / гипотеза) и уверенность.

## Как устроено

```
AGENTS.md            постоянные инструкции: роль, правила доказательности, безопасность, маршрутизация
workflows/           процессы: strategy.md (8 шагов, checkpoints C1–C3), update-decision.md (пересмотр)
skills/              методические навыки по шагам (формат SKILL.md; .claude/skills → skills)
knowledge/templates/ шаблоны артефактов 01–09
schemas/             JSON Schema реестра решения
tools/ledger.py      детерминированные проверки: validate, impact, trace, stats, status, init, add-source
projects/<case>/     sources/ (материалы) · state/ (progress, run_log, ledger) · outputs/ (результаты)
tests/               pytest для инструментов
docs/                ТЗ, требования, модель данных, план, журнал работы
```

## Ключевые решения

1. **Реестр решения вместо чата.** Источники, утверждения, гипотезы, варианты, решения, обещания и эксперименты хранятся связанными YAML-объектами ([docs/DATA_MODEL.md](docs/DATA_MODEL.md)). Это и есть память между сеансами, и в ней прежний ответ агента не становится фактом.
2. **Проверки и пересмотр — кодом, а не моделью.** `ledger.py validate` проверяет:
   - что у фактов есть источники;
   - что цитаты действительно есть в текстах;
   - что в решении есть вариант «оставить как есть» и что выбор сделал человек;
   - что источники не изменились незаметно.

   `ledger.py impact` находит ровно те выводы, которые задели новые данные. Модель переписывает только их.
3. **Один оркестратор и узкие помощники, а не рой агентов.** Субагент нужен только там, где он оправдан (верификатор утверждений на дешёвой модели).
4. **Человек решает.** Агент рекомендует, выбор и ответственность за человеком (checkpoints C1–C3).
5. **Безопасность.** Используются только открытые и собственные материалы. Текст источников — данные, а не инструкции. Ключей в репозитории нет (`.env.example`).
