# Четыре режима выбора маршрута — исправление дизайна

Запрос и уточнение пользователя 15.11.2026: D1; D1+Luna; Luna; no D1 no Luna.
Luna отключается **только как классификатор**. Исполнение и качество одинаковы.
Прежний pilot двух веток не является этим экспериментом; его данные сохранены.

| Режим | D1 классификатор | Luna классификатор |
|---|---|---|
| d1 | да | никогда, неуверенность оставляет manual |
| d1_luna | да | один вызов при валидном неуверенном ответе D1 |
| luna | нет | один вызов на задачу |
| none | нет | нет; заранее назначенные tier/effort |

Ошибки транспорта, политики и квоты не включают другой классификатор.
Luna-исполнитель и Luna-verifier сохраняются во всех ветках. Детерминированный T0
также одинаков. Таким образом сравнивается классификация, а не четыре разных
по качеству защитных контура. Доказательность цитаты не равна истинности ответа.

## Исправления перед новым pilot

- Исходные request/context/answer показаны verifier один раз без повторного JSON
  экранирования; буквальная проверка цитаты сохранена.
- Явный контракт расчётов задаёт исходные числовые поля, локаторы и выражения.
  T0 вычисляет значения до ответа и сверяет объявленные поля после ответа.
  Это часть одинакового рабочего процесса всех веток, не передача тестовых
  expectedfacts исполнителю. Не покрывает неописанные расчёты и остальные выводы.
- Неверный контракт останавливается до модельного вызова; неверный ответ не может
  получить accept только от LLM-verifier. Исправление — по прежней bounded лестнице.
- D1 deadline включает очередь и загрузку; по умолчанию120с. Отдельная cancel-by-ID
  операция отменяет pending работу без отмены остальных задач.
- Пороги D1 .75 / Luna labels .85 и taxonomy не подгоняются по десяти заданиям.
  Доля abstention и T1-review — результат, а не повод снизить порог ради таблицы.

## План pilot v2 (до вызовов)

Пять процессов-агентов с двумя последовательными шагами, barrier перед каждым шагом.
Новые ephemeral native threads; source/context независимы от ответа прошлого шага.
Один повтор четырёх веток в порядке d1 → d1_luna → luna → none:40 задач,
по10 на ветку. Это диагностический smoke после исправлений, не статистический
benchmark и не подтверждение универсальной экономии. CLI поддерживает второй
повтор в обратном порядке, но он не выполняется автоматически в этом pilot.

Кейсы four_cases.json получены из фиксированных five_cases.json: текст задачи и
сведения сохранены. Добавлены одинаковые явные источники чисел и выражения для T0;
они не содержат будущие сведения следующего шага. Routing получает исходный текст,
а исполнение — текст и контракт. Expectedfacts не попадают в model prompt.
Поскольку одновременно изменены представление verifier и T0-процесс, сравнение
с прежним pilot не приписывает весь эффект одному исправлению.

Настройки: quality max_attempts2, D1/native timeout120с, T4/max/ultra запрещены.
Текущая native подписка и установленный D1; новых API/ключей нет. Лимиты памяти
сохранены, отказ не заменяется скрытым fallback. Максимум два исполнения и две
проверки задачи, плюс один Luna classifier там, где он разрешён. Бюджет batch20мин.

Все raw start/end receipts, D1 ID/timing, статусы, исходные и переданные маршруты,
usage и неудачи сохраняются. Роль классификатора отделяется от task/verifier.
Сравниваются задержки, полнота выдачи, механические проверки и отдельный слепой
разбор качества. API-эквивалент считается отдельно от подписочных списаний,
локальной энергии и стоимости разработки. Нет отсутствующих расходов под видом0.

Прогон четырёх режимов не устраняет ограничение холодной загрузки на8ГБ.
Отмена/таймаут и восстановление проверяются отдельно от экономических веток.
