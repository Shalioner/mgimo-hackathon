# D1: качество классификации, 15.11.2026

Пользователь уточнил: сравнение квантования отменено, нужен новый тест качества
маршрутизации. Скачивание 4bit остановлено, незавершённый файл не используется.
Рабочие веса8bit, calibration, taxonomy, host config и порог0.75 не меняются.

20 новых синтетических задач:6 T1,6 T2,6 T3,2 T4. Независимое read-only ревью
проверило labels до inference. Q03/Q06 решаются кодом; T1 для них — ближайший
доступный label, поскольку taxonomy не имеет T0. Это ограничение учитывается
отдельно. В спорных normal/deep случаях заранее разрешены обе метки.

Один диагностический круг, фиксированное перемешивание seed20261115, четыре
пачки по5 клиентов одного текущего D1 service. Deadline действующей конфигурации,
лимиты памяти неизменны. Только классификация H.decide; без Luna, исполнителей,
T4-вызовов, изменения разрешений и внешних API. Frozen вопросы включают T4
из существующей конфигурации; отдельное разрешение исполнения не создаётся.

До inference сохраняются cases, questions, порядок, SHA кода и входов, service
status. Каждый ответ пишется отдельно. Отказы/потерянные ответы остаются в20.

Метрики: top1 согласие tier/effort/capability с инженерным эталоном; совместное
согласие tier+effort; уверенные маршруты при0.75; ошибки среди уверенных;
выбранные host-маршруты; правильные, но неуверенные предложения; причина отказа.
Capability оценивается отдельно: native host сохраняет инструменты, поэтому
его уверенность не должна отменять уверенный tier+effort. T4 policy denial
не считать ошибкой классификации. Время очереди/inference фиксируется по receipts.

Эталоны показывают соответствие проектной методике, а не эмпирически минимальную
модель, способную решить задачу. Один небольшой синтетический круг не доказывает
калибровку вероятностей или общую точность. По его результатам не снижать порог
и не менять labels. Старые10 кейсов можно разобрать отдельно как диагностику,
не смешивая с новым набором и не выдавая их за новые независимые наблюдения.
