# Сравнение с исходным способом: обычный чат vs агент «Стратег»

Пункт ТЗ «Сравнение с исходным способом»: «измерено, насколько агент быстрее, дешевле или точнее, чем аналитик вручную или обычный чат с ИИ, и какой ценой». Протокол зафиксирован **до** прогона базовой линии (коммит с этим файлом предшествует результатам). Результаты не подгоняются: рубрика и метрики не меняются после просмотра ответов. Неудачи тоже записываются.

## Кейс и условия
- Кейс `ryadom`: исходный запрос `projects/ryadom/sources/00_case_request.md`, ответ на C1 `01_c1_confirmation.md`.
- **Базовая линия («обычный чат»):** тот же запрос + уточнение C1 + **все 7 источников, которые нашёл агент** (02–08), одним сообщением; хороший промпт с перечнем того, что нужно получить (`prompt.md`). Это **фора чату**: сбор источников сделал агент, чат его не повторяет.
- Модель: та же, что у основной модели агента, — `gpt-6.1-sol`, effort `medium` (как в прогоне агента), Codex CLI без репозитория и инструкций агента (`codex exec` в пустой папке, только чтение).
- **Агент:** итоговый пакет `projects/ryadom/outputs/03–07` из E2E-прогона 1 (тот же Sol medium, с пересмотром по 08).

## Метрики
1. **Числа без опоры (кодом).** Все числа ответа (кроме ID, дат, номеров разделов) сверяются с текстом источников 00–08. Доля чисел, которых в источниках нет, — признак выдумки или нерасчётных оценок. Формат ответа не важен.
2. **Рубрика (10 вопросов «да/нет», `rubric.yaml`)** — по критериям ТЗ «Проработанность» и «Качество». Судья — модель решений (`tools/decide.py`, эмуляция на Luna: метка + дословная цитата, уверенность — по проверке цитаты кодом). Каждый документ оценивается **отдельно** по одним и тем же вопросам; документ подаётся без имени, но полностью слепой оценки нет — у агента видны ID реестра (ограничение).
3. **Время и стоимость:** токены из журналов (`tools/cost.py` для агента, `--json` usage Codex для чата) по ценам `knowledge/prices.yaml`.
4. **Чего нет у чата по устройству** (не баллы, а факт): сохранение состояния и продолжение, пересмотр только затронутых выводов, журнал. Отмечается качественно, без чисел.

## Решение по итогам
Пишем как есть: где агент лучше, где хуже, чего стоит разница. Если агент проиграл по метрике — так и пишем в CRITERIA и описании.

## Отклонение от протокола (записано до запуска судьи)
Первый подсчёт чисел кодом считал «числами» хвосты диапазонов ID (`EXP-001–005` → «005»), номера файлов-материалов (`02_google_location.md` → «02») и счётчики ≤ 10 («3 варианта», «шаг 4»). Это не утверждения о мире. Фильтр уточнён **одинаково для обоих документов**: исключены нулевые хвосты ID, ссылки вида `NN_файл`, целые ≤ 10 без дробной части. Первый «сырой» результат сохранён в отчёте: чат 20/54 (37%), агент 109/254 (43%).

## Условие 2 (добавлено после результата условия 1, записано до его прогона)
Условие 1 дало ничью по рубрике при фора чату (источники собрал агент). Реальный «исходный способ» — руководитель пишет в чат без материалов. **Условие 2:** тот же промпт и запрос + C1, **без материалов 02–08**, та же модель и effort. Метрики те же; числа сверяются с источниками 00–08 (чего чат не видел — то он взял не из материалов кейса).

## Метрика 5 (добавлена после прогонов условий 1–2)
Рубрика не различила документы (потолок у всех). После этого добавлена метрика **прослеживаемости**: доля строк с числами, где есть проверяемая ссылка — ID реестра, существующий в проекте, URL или ссылка на материал `NN_файл`. Считается кодом (`evals/compare.py`, `traceability`), одинаково для всех. Помечена как добавленная после результатов.
