## Отрицательный контроль и критерии

До NOTE.md все шесть намеренно испорченных записей были отклонены:

1. Сумма API-эквивалента выдана за платёж.
2. Календарный интервал выдан за активную работу.
3. Утверждённый предел EXP выдан за фактические часы.
4. Скрыт дополнительный ответ руководителя после CHG-001.
5. Неизвестная цена поиска заменена нулём.
6. Удалены кэшированные токены.

После доработки `negative-after.json` подтверждает те же отказы. `before` сохраняет ранние названия полей; затем неоднозначное `models` разделено на `window_models` и `result_models`. Смысл контрольной подмены не изменился.

Отдельные тесты добавлены по найденному риску атрибуции. Они проверяют исключение потока конкурента, отказ при подмене итогом широкого окна, отказ при дублировании потока и изменении исходного файла. Положительный контроль проверяет семь потоков, $3.0331, исключённые $0.2020 и календарные 7643 секунды.

Приёмка: извлечённые значения совпадают с evidence.json, хэши всех использованных файлов совпадают с заданной базой, присутствуют пять разделов записки и ключевые границы суммы/времени. Заголовки, наличие значений и существование относительных ссылок проверяет код; смысл, полноту атрибуции и корректность рекомендаций проверяет человек. Наличие раздела не доказывает его качество.

## Точные команды

Из корня checkout с установленными зависимостями `requirements.txt`:

```sh
base_dir=$(mktemp -d)
git archive 0888a8e5d92c2e62593bf5dccf9ee1da65ea1fe1 | tar -x -C "$base_dir"
.venv/bin/python evals/score9/cost-case/audit.py --root "$base_dir"
.venv/bin/python evals/score9/cost-case/audit.py --root "$base_dir" --controls
COST_CASE_BASE="$base_dir" .venv/bin/python -m unittest discover -s evals/score9/cost-case -p 'test_*.py' -v
.venv/bin/python "$base_dir/tools/ledger.py" validate "$base_dir/projects/ryadom"
```

Ожидаемый результат: аудит код 0 и `passed: true`; контроли код 0 и шесть `rejected: true`; шесть тестов OK; validate 58 объектов без ошибок и предупреждений. 58 относится к кандидату с поздним SRC-010, а не к срезу затрат 10 ноября. При отсутствии окружения сначала `python3 -m venv .venv`, затем `.venv/bin/pip install -r requirements.txt`.

Сохранённый снимок достаточен для офлайн-проверки. Для его независимого обновления нужны исходные журналы владельца. Необязательная команда на машине с этими журналами:

```sh
.venv/bin/python "$base_dir/tools/cost.py" --cwd e2e-ryadom --since 2026-11-10T14:00:00+03:00 --until 2026-11-10T18:00:00+03:00 --json
```

Эта команда воспроизвела $3.2351 и восемь потоков. Она использует фильтр cwd по подстроке; поэтому её результат сверялся с ID и метаданными каждого потока. Все восемь имели один полный рабочий путь. Для исключённого потока дополнительно прочитан собственный запрос, его короткая цитата сохранена в снимке. Встроенного снимка разговоров или платёжных документов нет. На машине без журналов команда не воспроизведёт денежный итог, это не нулевой расход.

- Локальный аудит после изменения: код 0, пять разделов покрыты, расхождений нет. Отрицательные контроли: шесть из шести отклонены.

- Дополнительно текущим `tools/ledger.py` проверен реестр распакованной базы: 58 объектов, ошибок 0, предупреждений 0. Текущий `tools/verify.py` на этих материалах дал 310 ok, 28 check и 24 unsupported из 362 строк. Это исходные ограничения общих артефактов; записка их не исправляет и не заявляет весь пакет полностью проверенным. Этот диагностический проход не является приёмкой новой записки.
- Первая консультация Gemini Hydrogen проверила исходную атрибуцию, отметила смешение 10 и 17 ноября, ширину окна, тарифные допущения и отсутствие стоимости труда. По её выводам проверены реальные метаданные потоков и обнаружено отдельное задание конкурента. Предположение консультации о непроверенной контаминации заменено прямой проверкой. Её ссылка на начало 14:17:53 не совпала с первой строкой run_log: для календарного интервала использована именно 14:20:35.
- Вторая консультация независимо подтвердила арифметику и границы. Она обнаружила восемь неверных относительных ссылок; они исправлены и проверены локальным проходом. В audit.py добавлен отказ на битые ссылки, в тесты положительный и отрицательный контроль ссылки. Замечание о различии времён токенов и журнала отражено в NOTE.md. Проверка текста по заголовкам остаётся ограничением, а не доказательством смысла.
