Окно — полный кабинетный проход до вердикта инициатора; активный труд ограничен 2 часами, не окном поведения жителей [EXP-001; HYP-004]. (проверено по CHG-001)
Предложение stop / go: сначала stop при нарушении, превышении лимита или явной бесполезности; затем полнота данных и go при корректных примерах и явной пользе [EXP-001]. (проверено по CHG-001)
Главный риск — принять формально заполненный Markdown за проверенный вывод; ложная карточка тоже проходит [CLM-009]. Приоритет и условия ниже ещё утверждает C3.

СИНТЕТИЧЕСКИЙ УЧЕБНЫЙ ПРОГОН. Discovery не доказывает спрос или причинный эффект и не служит основанием масштабирования. Технические наблюдения CLM-008/009 не являются результатом EXP-001 (пересмотрено по CHG-001).

## Логика исходов
Предложение к C3: stop → полнота → go. Это ещё не утверждённая политика [EXP-001]. (проверено по CHG-001)
- Положительный: все классы корректно трассируются И инициатор явно видит полезное изменение И труд в лимите. Следующий шаг — сохранить итог и обсудить внутреннее решение; не запускать сервис [EXP-001]. (проверено по CHG-001)
- Отрицательный: хотя бы один stop, включая явную бесполезность. Сохранить конкретную ошибку/причину, остановить дальнейший разбор, вынести вопрос инициатору; не компенсировать хорошими строками [EXP-001]. (проверено по CHG-001)
- Граница труда: ровно 2 часа допустимы при прочих условиях; более 2 часов — stop. Нулевой труд не доказывает состоявшийся полезный аудит [EXP-001; CLM-011]. (проверено по CHG-001)
- Формально заполненная карточка с неподходящим основанием: stop по неверному переносу, а не успех форматирования. Измеримый следующий шаг — указать ошибочную строку и недостающий источник [CLM-009; EXP-001]. (проверено по CHG-001)
- Одновременные stop/go: stop важнее, даже если инициатор видит пользу; зафиксировать сработавшее ограничение и остановить продолжение [EXP-001]. (проверено по CHG-001)
- Серая зона: все материалы есть, но полезность неоднозначна. Сохранить полный результат, запросить явный вердикт инициатора, не расходовать дополнительный труд и не масштабировать [EXP-001]. (проверено по CHG-001)
- Неполные данные: известный stop действует сразу; без stop, но при пропущенной строке или отсутствии вердикта — недостаток данных. Перечислить недостающие поля/ответ и удержать go до их получения [EXP-001]. (проверено по CHG-001)
- Отсутствие ухудшения не означает улучшения. Discovery не даёт причинного эффекта; формальное прохождение CLI не заменяет содержательный результат [CLM-009; EXP-001]. (проверено по CHG-001)

## Отказ CLI и восстановление до содержательной оценки
Эта ветка дополняет EXP-001, не вводя новый лимит или факт полезности. Неполный вход уже наблюдался как `exit 2` без нового файла [CLM-008]. Отказ не является успешной карточкой и сам по себе не доказывает отсутствие полезности [EXP-001] (пересмотрено по CHG-001).

| Наблюдение | Статус строки | Следующее действие аналитика |
|---|---|---|
| `exit 2`, ошибка неполных полей, нового файла нет | Технический отказ, не успех | Сохранить вход и stderr; в копии заполнить только отсутствующие/пустые поля по проверенному материалу; заполненные поля сохранить; повтор планировать лишь в оставшемся общем лимите труда HYP-004 [CLM-008; EXP-001] (пересмотрено по CHG-001) |
| Поля исправлены, но команда ещё не запускалась | Повтор запланирован, не выполнен | Запустить ту же команду с исправленной копией и новым выходным путём только при достаточном остатке лимита; записать реальный код/выход; до этого строка удержана [EXP-001] (пересмотрено по CHG-001) |
| Реальный повтор дал `exit 0`, новый файл соответствует исправленной карточке | Оформление выполнено, содержание ещё проверяется | Отметить технический успех отдельно, затем вручную сверить основание и перейти к содержательным stop/go; истина автоматически не проверена [CLM-008; CLM-009; EXP-001] (пересмотрено по CHG-001) |
| Есть прежний файл, но отказ/код неизвестен/новый файл не подтверждён | Успех не подтверждён | Не засчитывать старый файл, удержать строку и передать инициатору конкретную неопределённость [EXP-001] (пересмотрено по CHG-001) |
| Нет основания заполнить пропуск, остаток лимита исчерпан, ошибка иная или повтор снова отказал | Удержание, go не допускается | Сохранить дефицит, код и фактический труд, обратиться к инициатору; не придумывать текст, не расширять лимит и не продолжать цепочку повторов [HYP-004; EXP-001] (пересмотрено по CHG-001) |

В лимит 2 часа входят все попытки, диагностика, исправление и ручная сверка [HYP-004; EXP-001]. Неполная/неоформленная строка остаётся в знаменателе заданных классов CLM-006 и не попадает в числитель корректных примеров; отказ не создаёт положительного результата. Если требование труда уже превышено, действует прежний stop; если лимит достигнут и нужны дополнительные действия, удержать материал без новых затрат до решения инициатора [EXP-001] (пересмотрено по CHG-001).
Эта инструкция описывает будущий внутренний проход после C3. Локальная техническая перепроверка процедуры фиксируется отдельно в state/refusal-recovery-recheck/receipt.json; она не является результатом EXP-001 или EXP-002 и не подтверждает полезность или реализуемость всего разбора в лимите [EXP-001; EXP-002] (пересмотрено по CHG-001).

## Ранние сигналы
Сомнительная цитата, несовпадение сегмента/поверхности или заявление, что CLI проверяет истину, — повод удержать конкретную строку и сверить источник вручную. При приближении к лимиту аналитик фиксирует фактически затраченное время; новый неутверждённый порог тревоги не вводится [CLM-009; EXP-001]. (проверено по CHG-001)
Реальное измерение неявок потребовало бы своей площадки, определения события, знаменателя и разрешений; в текущем пакете этого нет [CLM-005; DEC-001]. (проверено по CHG-001)
