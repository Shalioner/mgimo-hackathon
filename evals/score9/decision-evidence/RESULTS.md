# Наблюдения и границы проверки

Среда: Codex в T3 Code. Baseline c77ecd6. Протокол записан до реализации.
Выбран диспетчер применимости свидетельств, встроенный в skill alternatives.
Это продуктовый инструмент: новый JSON → локальная команда → короткое предложение
для C2 с проверяемыми основаниями; ни сеть, ни LLM для воспроизведения не нужны.

## Сравнение с исходным поведением

Baseline уже умел анализировать чувствительность, просил факторы смены ранжирования
и имел econ.py. Новое поведение — не исправление отсутствующего калькулятора.

M27, `projects/rehearsal-mobile-spend/outputs/04_options.md`: baseline рекомендовал
макет отчёта, а руководитель выбрал предупреждения. Различие денежного перерасхода
и снижения скорости уже было замечено в тексте; мы не выдаём это за новое открытие.
Новый запуск `m27.json` явно предлагает сегодняшнюю правку сценария перед интеграцией,
показывает неизвестную готовность пилота, связывает её с собственными наблюдениями,
проверяет влияние удаления источника. Не утверждает, что изменил выбор руководителя.

Контраст — `projects/esim-travel/outputs/04_options.md` baseline: рекомендация своего
white-label продукта при неизвестных удержании и затратах. Новый `esim.json` не
сравнивает его окупаемость заново. Он отсекает безусловную совместимость с iPhone и
предлагает проверку разблокировки в прототипе входа. Ресурс на коммерческий запуск
не выделяется, неизвестная доля совместимой базы не заменена выдуманным охватом.
Условия постановки сценариев и порядок действий — явные допущения, не ответы клиента.

`insufficient.json` использует постановку «Рядом»: собственные причины ухода
неизвестны; наблюдений нет, ни одно необходимое условие не подтверждено.
Выход: отказ от стратегической рекомендации, вопрос о собственной проверке, код 2.
Нельзя интерпретировать его как совет закрыть или автоматически исследовать продукт.

## Реальные первичные наблюдения

2026-11-19 получены два полных публичных документа, сохранены короткие точные
выдержки, URL/локаторы/даты и SHA-256 в JSON. PDF извлечён pdftotext -layout;
хэши исходных загрузок — sources/capture-hashes.json. Для воспроизведения нужны
только локальные выдержки, исходные загрузки удалены. МегаФон — один тариф СПб/ЛО,
после всех доступных пакетов: ограничение скорости. Apple — два разных оператора
на iPhone: условие разблокировки. Первичность и смысл привязок проверены вручную;
сам код проверяет целостность, дату и область, не истинность смысловой интерпретации.

Отрицательный контроль `m27-negative.json`: реальная розничная абонплата из того же
PDF добавлена как фон. Ни рекомендация, ни допуск вариантов не меняются. Чужая цена
не становится нашей себестоимостью. Тест также запрещает перенос открытой документации
в условие own_outcome и на другую область. Мнения клиентов не моделировались.

## Воспроизведение

Из корня проекта:

```sh
python skills/alternatives/decision_evidence.py evals/score9/decision-evidence/m27.json
python skills/alternatives/decision_evidence.py evals/score9/decision-evidence/esim.json
python skills/alternatives/decision_evidence.py evals/score9/decision-evidence/m27-negative.json --json
python skills/alternatives/decision_evidence.py evals/score9/decision-evidence/insufficient.json
python -m pytest -q evals/score9/decision-evidence/test_decision_evidence.py
```

Первые три команды: код 0; четвёртая: ожидаемый код 2. Сохранённые .md и
.result.json — фактический stdout. Тесты после исправлений ревью: 9 passed. Они проверяют поведение,
не считаются доказательством полезности руководителю. Даты снимков фиксированы:
для нового решения сегодня источники нужно перепроверить и обновить as_of/review_by.

## Консультации и ограничения

Две консультации Gemini 4 Hydrogen запрошены через T3/Antigravity, без платного API:
перед реализацией — независимая постановка; после — ревью точного patch.
Первая подтвердила разрыв между сегодняшним действием и отложенной ставкой;
предупреждение о дефолте в исследование учтено: status_quo/kill конкурируют на равных.
Второе ревью завершено: подтверждена применимость механики, найдены три
воспроизводимых дефекта. Они проверены и исправлены без нового делегирования:
короткий вывод теперь показывает scope, значения условий и конфликт; eSIM связывает
собственный эффект/затраты с отдельным условным коммерческим пилотом; невалидные
формы JSON возвращают отказ без traceback. Пустой список наблюдений допустим.
Сценарий «Рядом» разделён на четыре независимых основания: подтверждение причины
больше не разрешает масштабирование или закрытие. Все новые формы проверены CLI/тестами.
Повторного независимого ревью исправленного patch не проводилось.

Это офлайн сценарная проверка механики и переноса, не слепой LLM A/B и не исследование
с руководителями. Время принятия решения, сэкономленные деньги, рост удержания и
оценка 9/10 не измерены. Правило приоритета и полнота необходимых условий задаются
людьми/агентом до запуска; утилита не может обнаружить забытое условие по смыслу.
C1–C3 и реальные DEC не изменены. Реестры проектов не записывались.

Ошибки среды: длинный генератор JSON дважды дал ошибку чтения UTF-8 Python; файл
проверен на UTF-8, исполнение через compile(read_text(encoding='utf8')) прошло.
Первичная сборка patch без new file mode не применялась вне Git; добавлен корректный
заголовок новых файлов. Эти ошибки не относятся к данным и не скрыты тестами.

## Проверка поставки

Patch применён к отдельному архиву c77ecd6. Специфичные тесты в нём после исправлений: 9 passed;
существующие tests/test_options.py: 14 passed. Исходный текст skill baseline
сохранён полностью перед новой секцией. git diff --check рабочего дерева — без ошибок.
Область patch машинно проверена: только skills/alternatives и эта папка.
В текущем checkout skill старее baseline; применяйте именно patch, не diff HEAD→worktree.

Ограничения контрфактической механики: удаляется один факт за раз; дублирующие
доказательства могут маскировать влияние каждого в отдельности. Вопросы проверяются
по одному; несколько совместно необходимых ответов могут не переключить лидера
поодиночке. Пустые requires у status_quo/kill означают явно допустимый запасной путь,
а не обязанность отказать. Полный отказ возникает при отсутствии оснований для всех
действий, как в «Рядом»; способ задания необходимых условий влияет на результат.
