# Эксперимент 5. Сухой проход по тексту F1

Проверен [зафиксированный текст макета](../../../projects/family-connect/sources/f1-family-signal-consent-v2.md) по сценарию EXP-001. Проход выполнялся как ручное чтение состояний и переходов на вымышленных вводных. Он проверяет наличие предусмотренного правила, без запуска интерфейса, биллинга и опроса пользователей.

| Сценарий | Ожидаемый исход из текста макета |
|---|---|
| Молчание или отказ | Организатору закрыты остаток и сигнал, участник видит свои сведения. |
| Показ разрешён, права выдачи нет | Остаток доступен в пределах разрешения, недоступная выдача не предлагается. |
| Условия выполнены и остаток свежий | Сигнал только в кабинете, действие повторно проверяет условия. |
| Неясная причина, неоплата или устаревшее событие | Сигнал отсутствует, сведения об оплате закрыты. |
| Отзыв при открытой карточке и старая ссылка | Открытая карточка убирает сведения после обновления прав, новое открытие снова проверяет доступ. |
| Отзыв до необратимого вычета | Обратимый вычет отменяется, сведения об операции закрываются. |
| Отзыв после необратимого вычета | Биллинг сверяет операцию внутренне, организатор не видит квитанцию. |
| Повтор идентификатора | Второго вычета нет по правилу, результат зависит от разрешения. |
| Остаток общего пакета закончился | Вычет блокируется при повторной проверке. |

**Наблюдение.** Для всех 9 строк в макете есть ожидаемый исход. При открытой карточке текст оставляет интервал до получения обновления прав. Максимальная длительность этого интервала и поведение при сбое доставки остаются неизвестными. Для тестового контура добавить отдельный контроль «отзыв → потеря или задержка обновления → попытка действия и повторное открытие». Пользовательскую понятность и фактическую защиту этот проход не измеряет.
