# Картина ситуации

## Главное

Подсказка прошла точечные пороги учебного пилота. Точность сортировки выросла на +8 п.п., а доля обращений в тесте составила 3% [CLM-009].
Уверенность в арифметике высокая. Интервалы пересекают оба бизнес-порога, поэтому повторная проверка может изменить вывод [CLM-010].
Для этикетки пока нет сравнимого результата, а стоимость пересортировки неизвестна [CLM-001] [CLM-005].

**Счётчик по реестру:** 8 фактов, 4 интерпретации, 2 гипотезы, 0 противоречий. Три существенных пробела перечислены по вопросам ниже.

## Q1. Исходы пилота [R2]

**Известно.** На одном учебном складе операторов случайно распределили по веткам. В знаменатель входят все назначенные операторы. Оператор представлен своим первым подходящим закрытым коробом. Типы подходящих возвратов совпадали. Окно по каждому исходу — 24 часа. Пропусков и дублей нет по описанию, сама таблица агрегирована по веткам [CLM-002] [CLM-003].

| Исход | Текущий экран | Подсказка | Разница |
|---|---|---|---|
| Правильная зона без повторной маркировки | 216 / 300 = 72% [CLM-008] [CLM-009] | 240 / 300 = 80% [CLM-008] [CLM-009] | +8 п.п. [CLM-009] |
| Хотя бы одно обращение к начальнику смены | 6 / 300 = 2% [CLM-008] [CLM-009] | 9 / 300 = 3% [CLM-008] [CLM-009] | +1 п.п. [CLM-009] |

**Интерпретация.** Процент — счётчик исхода, делённый на `assigned` в той же ветке. Разница — доля теста минус доля контроля. Для вреда сравниваем с порогом абсолютные 3% в тесте. По сводке и описанию известны исходы всех 600 назначенных, доля пропусков 0% [CLM-003] [CLM-004] [CLM-008] [CLM-009].

Для разницы качества двусторонний 95% интервал Ньюкомба от +1,16 до +14,75 п.п. Для доли обращений в тесте двусторонний 95% интервал Уилсона от 1,59% до 5,60%. Для воспроизведения границ разницы строим интервалы Уилсона для обеих долей через `tools/power.py wilson`. Из разницы долей вычитаем корень из суммы квадратов расстояний до нижней границы теста и верхней границы контроля. Для верхней границы прибавляем корень из суммы квадратов расстояний до верхней границы теста и нижней границы контроля [CLM-010].

**Неизвестно.** Воспроизведётся ли выигрыш не ниже порога при допустимой доле обращений. Одна агрегированная выборка даёт интервалы, пересекающие пороги. Это проверит повтор с теми же определениями исходов после отдельного согласования [CLM-004] [CLM-006] [CLM-010] [HYP-001].

## Q2. Готовность и причина ошибок

**Известно.** Стенд показал код после ручного подтверждения зоны и до закрытия короба. Без подтверждения кода нет. Этикетку с операторами ещё не проверяли. Подготовка и стенд допустимы, для проверки на реальных сменах нужно отдельное согласование [CLM-001] [CLM-006] [CLM-007].

**Интерпретация.** Стенд подтверждает поведение интерфейса. Для выбора между экраном и этикеткой важно выяснить момент ошибки [HYP-002].

**Неизвестно.** Как часто ошибки возникают при чтении физической этикетки. В сводке нет этапа и причины ошибки. Это можно установить по наблюдениям за маршрутом короба и разбору случаев пересортировки [HYP-002].

## Q3. Экономика

**Известно.** Смета на неделю составляет 36 000 ₽ при потолке 50 000 ₽ [CLM-005].

**Интерпретация.** Запас по смете составляет 14 000 ₽. Из исходов пилота нельзя напрямую вывести денежную выгоду [CLM-011].

**Неизвестно.** Чистый вклад подготовки подсказки, этикетки и высвобождения ресурса. Нужны стоимость повторной маркировки, оценки работ по вариантам и ценность альтернативной задачи команды [CLM-005] [CLM-011].

## Проблема оператора и гипотезы

У операторов возвратов возникают короба, которые не проходят приёмку в правильной зоне без повторной маркировки. Частота исхода и обращения измеряются. Стоимость для оператора и результат обращения не измерены [PAIN-001].
Главное основание подготовки повторной проверки — пересчёт пилота [CLM-009]. Сильное ограничение — ширина интервалов [CLM-010]. Повторяемость результата и момент возникновения ошибки остаются гипотезами, способными изменить выбор [HYP-001] [HYP-002].
