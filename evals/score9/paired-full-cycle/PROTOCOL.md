# Сравнение полного цикла на новой задаче

Сценарий сортировки возвратов составлен отдельно. В файле `case.json` зафиксированы данные, пять реплик и восемь признаков результата. Сценарий синтетический. Выпуск модели и параметры одинаковы у обычного чата с терминалом, исходной версии Стратега и версии с сокращённым процессом. Обе версии Стратега распаковываются из точных локальных коммитов. Реплики одинаковы, поправка появляется только после C3. Первые четыре реплики идут в одной сессии. Пятая начинает отдельную по сохранённым файлам. В рабочие папки попадают только разрешённые входы и, для Стратега, его репозиторий. Рубрика и ожидаемые ответы в них не передаются.

Оценщик получает обезличенные ответы и сохранённые результаты без времени, расходов и названий режимов. Ему передают также рубрику. Целостность C3 и переходы состояния рассчитываются отдельно из снимков CLI. Один балл за каждый выполненный пункт, критические провалы фиксируются отдельно.

Критерий принятия сокращённого процесса: при сопоставимом качестве с исходным Стратегом, без критического провала и с действительной квитанцией C3, wall time или API-эквивалент меньше минимум на четверть в этом опыте. Любое ухудшение второй метрики указывается. Для обычного чата применяется та же рубрика. Уменьшение расходов относительно исходного Стратега само по себе не доказывает выигрыша над чатом.

Время каждой ветки — сумма времени пяти команд CLI, включая ошибки команд внутри этих окон. Фиксируются команды, сбои, завершённые реплики, SHA-256 условий, состояние файлов на остановках. Для затрат берётся последний накопительный снимок каждого отдельного чата. Активное время руководителя не измеряется: реплики подаёт скрипт. Проверка проводится по действующей подписке без API-ключей. Одна пара на дизайн характеризует наблюдавшиеся ответы. Хост общий, параллельный запуск может влиять на время. Входы, rubric, код и версии фиксируются до любого запуска модели.

## Повтор после обнаруженного сбоя C2

В первом прогоне сокращённый процесс предъявил C2 с двумя недопустимыми осями и без распознаваемого правила выбора. Поэтому эта версия не проходит критерий принятия, даже если время и расходы улучшатся. Первый прогон сохраняется. Второй сокращённый вариант добавляет единую проверку C1, C2, C3. Перед его запуском сохраняем те же входы, реплики, модель и критерии оценки. Повторяем только изменённую ветку, исходный Стратег и обычный чат остаются контролями из первого замера. Часть окон проходит в разное время. Сравнение времени между прогонами менее надёжно, чем сравнение токенов и поведения. После прогона дополнительно проверяем действующие ворота до C2, отсутствие записи C3 до ответа и совпадение предъявленного SHA с квитанцией.

Обнаружена ошибка распаковки: короткие версии содержали в рабочей папке каталог этого опыта, включая рубрику и позднюю поправку. Их первые запуски не считаются изолированными. Первый сохраняется как диагностический. Первый запуск версии с проверкой этапов остановлен на C1. Повтор этой версии удаляет из распаковки только каталог эксперимента и сохраняет список исключений в `frozen.json`. Контрольные ветки не содержали этого каталога.

Во время повтора обнаружили полную копию архива в родительском каталоге. Её перенесли после третьей реплики. В обработанных командах нет обращений к архиву, рубрике или хэшам входов. Реплики ограничивали чтение рабочей папкой, а файловая система допускала чтение родительского каталога. В дальнейшем распаковка получает поток Git без записи промежуточного архива.
