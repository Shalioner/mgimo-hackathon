## Как повторить

Из корня рабочей копии с Git и подготовленной `.venv`:

```bash
.venv/bin/python evals/score9/stack-benchmark/run.py --repeats 5 --jury-repeats 2 > /tmp/strategist-stack-baseline.json
```

Для сравнения форматов `verify` использовали `tools/verify.py projects/family-connect --files 03 04 05 06 07 --strict` с `--json` и отдельно с `--sample 8`. Оба вызова завершились кодом 0. Байты считали по stdout.

- Локальная команда выполняется один раз для прогрева и пять раз для замера. Время включает запуск процесса, чтение, вычисление и захват вывода. Команды запускаются последовательно при обычной нагрузке машины. Сами кейсы проверяются по SHA-256 до и после. HTML собирается во временную папку. Инструменты работают с отдельным `HOME` без пользовательских маршрутов и секретов.
- Контроль «возврат к кейсу» выполняет одни и те же четыре действия на `family-connect` и `esim-travel`: статус, очередь, сводка объектов с отозванными записями и проверка C3. Вариант A — четыре отдельных запуска Python, вариант B — те же CLI-функции внутри одного процесса. После прогрева порядок A/B чередуется. В каждом повторе совпадают код выхода, stdout и stderr для каждого действия. Это тест механической части продолжения.
- Прогон жюри начинается заново на временной копии. Он проверяет официальный семейный кейс, сохранение готового брифа на открытом C1, выбор руководителя вопреки рекомендации, открытое повторное C3 и отрицательные контроли. Сборка брифа моделью и ожидание человека в этот замер не входят.
- Размеры считаются в байтах UTF-8. Размер каталога MCP — сериализованные описания 11 инструментов сервера. Это верхняя граница при загрузке целого каталога в таком формате, а не измерение контекста модели. RTK проверяется на двух одинаковых командах Git. Сокращение вывода отражает один вход и само по себе ничего не говорит о стоимости сессии.

## Что используем в архитектуре

| Механизм | Что есть в «Стратеге» | Что проверять дальше |
|---|---|---|
| Подгрузка инструментов | Сервер возвращает статический каталог MCP. Подгрузка описаний зависит от клиента. `tool_router.py` выбирает одно действие из списка до восьми кандидатов. `route_tools.py` выполняет только разрешённое хостом действие. | Замерить фактические схемы и обращения в конкретном хосте. Сокращать каталог при подтверждённой доле в контексте. |
| Объединение вызовов | Есть пакетная проверка файлов и вопросов, а разбор документов извлекает карточки последовательно. Общего вызова `resume` в продукте пока нет. | Сделать read-only сводку через существующий Python-код и при необходимости выставить её через тот же MCP. В прототипе четыре действия собраны в один локальный процесс. |
| Сжатие вывода | `ledger brief`, точные локаторы и карточки источников ограничивают объём чтения. `tool_context.py` отдельно обрабатывает экспорт истории и сохраняет защищённые результаты. | Выбор моделей | Может запускаться явным маршрутом. Установка hook в хосте и подтверждённое исполнение выбранной моделью проверяются отдельно. | Сравнить встроенную обработку T0 с дополнительным классификатором только на запросах, где действительно нужен выбор. Считать накладные расходы и ошибки маршрута вместе. |

В этом сеансе T3 отдельные инструменты `strategist_*` не представлены. Диагностика проектного Codex-адаптера вернула `needs_setup`, `registered: true`, `enabled: false`. ### Code Mode в Claude Code

Экспериментальный **Code Mode** позволяет модели написать JavaScript, который в рамках одного шага выполняет цепочку инструментов и возвращает выбранный результат. Официальная документация указывает версию Claude Code от 2.1.323, совместимую модель и интерактивный терминал. Здесь установлена версия 2.1.311. Сравнение на поддерживаемой сборке планируется как отдельная пара, а пользовательские настройки пока не менялись. [Документация Claude Code](https://code.claude.com/docs/en/code-mode).

**Tool Search** решает отдельную задачу: экономит контекст на описаниях MCP. У Anthropic API есть **Programmatic Tool Calling**. У Cloudflare Code Mode может выставлять две операции поиска и исполнения для большого API. Фиксированный `resume` «Стратега» проверяет только полезное для текущего сценария свойство: собрать результат нескольких действий в одном вызове. [Tool Search](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search) · [Anthropic API](https://platform.claude.com/docs/en/agents-and-tools/tool-use/manage-tool-context) · [Cloudflare Code Mode](https://blog.cloudflare.com/code-mode-mcp/).

## План чистого сквозного сравнения

1. Зафиксировать полный архив сборки и его SHA-256, версии Python и клиента, модель и effort, подключённые инструменты и разрешения. Устанавливать baseline и вариант в разных папках. В обеих ветвях использовать одинаковые входы и ответы сценарного руководителя. Сначала проверить чистый старт и образцовые кейсы, затем прогонять серии в свежих сессиях.
2. Измерять три маршрута отдельно: полный цикл от первого запроса до утверждённого C3 и сопровождения, частый read-only возврат к семейному кейсу и eSIM, пересмотр после нового источника. Для извлечения документов включить сбой на третьем из четырёх источников и сравнить повтор всех карточек с восстановлением сохранённых.
3. Для сравнения команд и Code Mode начинать с пяти чередующихся пар на каждом типе задачи. Отдельно фиксировать холодный и прогретый запуск, ожидание ответа человека, его активное время, время до полезного ответа, число инструментальных заходов модели и внутренних вызовов инструментов. Собирать обычные входные, кешированные и выходные токены по ID всех потоков, включая ревью и повторные попытки. API-эквивалент и фактический платёж вести отдельными полями.
4. До сравнения скорости проверить, что оба режима правильно восстановили выбор, C3, открытые CHG и отозванные обещания. При полном проходе дополнительно проверить ссылки, происхождение ключевых выводов и правила C1–C3. Ошибки и незавершённые ответы остаются в знаменателе. Режим проходит, когда качество сохраняется и разница времени превышает обычный разброс.
5. Для **Claude Code Code Mode** сравнить режимы на одной поддерживаемой версии и модели, оставив настройки Tool Search, RTK и набор MCP одинаковыми. Затем при необходимости замерить Tool Search отдельно. В T3 Code сравнивать штатные обращения с одним фиксированным чтением через CLI. Переносить выводы между хостами только после проверки.

## Приоритеты оптимизации

1. Довести явное подтверждение C3. Ошибка записи отказа воспроизведена в отдельной копии. Эту корректность проверяем перед сравнением ускорений.
2. Сделать фиксированную операцию возврата к кейсу, которая одним вызовом возвращает разрешённое следующее действие и его основание. Сначала принять семейный кейс и eSIM. Вариант экономии на следующих шагах — отдельно измерить сокращение подробных выводов `verify` и `trace` с полным результатом по запросу.
3. Проверить вынос справочного раздела о маршрутизации из постоянно загружаемого контекста, оставив правила C1–C3, уровни и ограничения на месте. Сейчас `AGENTS.md` занимает 40 204 байта. Claude Code и T3 могут подгружать проектные инструкции по-разному, поэтому выигрыш в токенах нужно сравнить на одном хосте. Продолжение разбора с сохранённых карточек измерять отдельным сценарием частичного сбоя.
4. Начать эксперимент Code Mode с типовой цепочки чтения и проверки. Общий интерфейс исполнения произвольного кода добавлять только при измеренном выигрыше на сценариях, которые фиксированная команда не покрывает. Порог сначала определяет качество результата и сохранение полномочий, затем время и расход.
