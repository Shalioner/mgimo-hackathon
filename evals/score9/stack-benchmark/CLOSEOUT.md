# Замеры перед оптимизацией «Стратега»

База — рабочее дерево от `e89f775`. Новые замеры дополняют [локальный бенчмарк](README.md) и [замеры D1 и T3](EXTENSION.md). Продуктовую логику и записи действующих кейсов не меняли. В опыте с повтором разбора меняли только тестовый транспорт.

Строка про C3 ниже фиксирует исходный дефект. Текущая версия проверяется отдельным [контролем записи в сценарии жюри](../jury/run.py). Он проверяет пять отказов до записи, одно явное согласие и сохранение байтов при повторе на временной копии.

## Что отделить при закрытии идей

1. **E3 — исправить C3 первым.** Добавить точную проверку явного решения по предъявленной версии. Повторить все шесть контролей. Для отказа, условного ответа, подтверждения чтения, пустого ответа и старого хэша допустимо ноль записей. Явное согласие и повтор должны остаться проходимыми.
2. **R2 — сделать read-only команду `resume`.** Локальный выигрыш около 1,8 с при одинаковом выводе подтверждён десятью парами. Пакетная ветка в новом запуске T3 также не выполнила команду, поэтому 22,8 с обычной ветки остаются единственной живой точкой. Живой A/B требует прямого запуска обеих ветвей в подходящих сессиях. [Сквозной бенчмарк — пакетное чтение eSIM](t3-thread://v2/04137f2b-7a46-4f5d-b68f-9ec703c6ac6a/thread:delegated-task:command%3Amcp%3A9f6c3689-0e58-42a2-a282-c0fe164c560f%3Adelegate-task%3Ad6879592-cfd5-4220-ba94-92b04694c3a6).
3. **R1 — реализовать возврат к проверенным карточкам.** Начать с явного продолжения от сохранённого результата. Проверять хэши источника и инструкции, профиль исполнения и повторную валидацию карточки. Закрытие — 5 попыток вместо 7 в контрольном сбое, ноль устаревших переиспользований и замер на живом транспорте.
4. **E2 — оставить как ограниченный контроль.** У обычной инструкции 10/10. Повтор нужен на задачах, где стандартный ответ действительно преждевременно меняет вердикт. Для такой правки отдельно проверяется немедленная реакция на подтверждённый стоп.
5. **U3 и карточка C3 — проверить с руководителями.** Для запроса ресурсов проверить, помогает ли формулировка «наблюдение → следующее решение». Для карточки готов протокол точности и времени. Техническая проверка материалов пройдена ранее, данных живых участников нет. [Карточка и протокол](../factory-experiments/approval-card/README.md).

Для четырёх коротких источников выбор по умолчанию — один ведущий с явной проверкой права выдачи. В контроле это дало тот же балл без передачи между агентами. Параллельный разбор стоит проверять отдельно на более крупных пачках, с повторами и полным учётом расхода всех исполнителей.

## Блокеры сквозных замеров

- **Claude Code Code Mode.** На машине версия 2.1.311 и `loggedIn: false`. Для проверки нужны совместимая версия и авторизованный интерактивный терминал. Настройки и аккаунт в этом прогоне не менялись. [Документация Claude Code](https://code.claude.com/docs/en/code-mode).
- **Живой цикл C1–C3.** Чистая установка и воспроизведение готовых кейсов подтверждены. Для свежего полного цикла нужны зафиксированный вопрос руководителю, три его ответа, активное время и учёт всех потоков. Новые пользовательские решения из синтетических ответов не записывались.
