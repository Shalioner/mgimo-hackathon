# Проверка смысловой поддержки

Версия корпуса: 1, 2026-11-15. Все примеры синтетические, внешним фактом не являются.
Это небольшая регрессионная выборка, не оценка точности на всём потоке задач.

В `cases.json` зафиксированы девять осей, у каждой ошибка и корректный контроль.
Для независимого судьи передавать только `id`, `source`, `text`, перечень меток
и определения; `expected`, `rationale`, имя оси и порядок пар скрыть, порядок перемешать.
Вердикты: ok — допустимо; unsupported — основания нет; overstated — завышен вывод;
wrong-ref — дано основание другого свойства/периода; not_distinct — варианты одинаковы;
inconsistent — условие противоречит исходному. Обнаружение дефекта и точную метку
анализировать отдельно: разные метки ошибки не равны пропущенному дефекту.

Ответ судьи — JSON-объект `{id: verdict}`. Сохранить модель, effort, версию промпта,
входные/выходные токены, время, стоимость и все ответы, включая ошибки. Повторные
попытки учитывать, результат не выбирать по лучшей попытке. Не называть машинную
проверку корпуса или проверку scorer замером качества LLM.

Бесплатная подготовка (без модели):

```bash
.venv/bin/python evals/semantic/score.py
```

Оценка уже полученных ответов:

```bash
.venv/bin/python evals/semantic/score.py --answers /path/to/answers.json
```

Предлагаемый барьер для этой небольшой выборки: ни один ошибочный пример не получает
ok, ни один корректный не отклонён. Даже полное прохождение не доказывает готовность
на новых данных. В этом исправлении модельный прогон не проводился; платные вызовы
требуют отдельного разрешения. Рабочая проверка перед C3 описана в
`skills/claim-verifier/SKILL.md` и сохраняет ручной разбор сомнительных оснований.
