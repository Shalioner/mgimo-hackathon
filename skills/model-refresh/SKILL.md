# Обновление моделей и гайдов вендоров

Уровень: **T0 → T1**. Сравнение — кодом, чтение источников — дешёвой моделью; T3 только если правила вендора противоречат друг другу.

1. `python tools/models.py scan`, затем `python tools/models.py check`. Работай **только** по пунктам из вывода — не перечитывай все гайды «на всякий случай».
2. **НОВАЯ ВЕРСИЯ** — модель уже используется автоматически (шаблон в `routing.yaml`). Проверь в гайде вендора, не изменились ли правила для новой версии (effort, контекст, запреты параметров). Если человек согласен — `python tools/models.py apply`, чтобы обновить запасной ID.
3. **НЕТ ГАЙДА** — добавь шаблон модели в `covers` нужного файла `knowledge/model_guides/<вендор>.md`. Нового вендора — новым файлом по образцу существующих (шапка + 5–8 правил «что применяем»).
4. **ГАЙД УСТАРЕЛ** — открой только ссылки из `sources` этого гайда (официальные страницы вендора). Обнови правила, `delegate_hints` (короткие подсказки, которые `delegate.py` добавляет в задания), поставь `checked: <сегодня>`.
5. Правила — пересказ своими словами со ссылкой на источник, без копирования текста. Сторонние блоги — не источник.
6. Проверка: `python tools/models.py check` → «Новых версий нет, гайды актуальны»; `python -m pytest -q tests`.
7. Запись: если обновление шло во время работы над кейсом — `python tools/ledger.py log projects/<case> --step model-refresh --action "…" --result "…"`; иначе — в сообщении коммита. Продуктовый реестр не трогается.
