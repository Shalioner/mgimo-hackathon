# Анализ влияния новых сведений

Полный порядок действий — `workflows/update-decision.md`. Здесь главное.

**Косметическое изменение.** Несовпадение sha256 требует сверки источника. Сравни версии по фактам, периоду, сегменту, единицам и цитатам, на которые опирается решение. Если изменилось только оформление, запиши проверку и сохрани выводы, выбор и состояние согласований. Для изменения файла на месте восстанови прежнюю версию из доступного снимка и регистрируй новую версию отдельным SRC при необходимости. Если прежний файл недоступен, зафиксируй блокер проверки целостности.

1. Прочитай `ledger.py brief projects/<case> DEC-NNN CHG-NNN` и вычисли граф влияния `ledger.py impact projects/<case> CHG-NNN`. Открывай `trace` по отдельному основанию, когда оно нужно для вывода. При расхождении графа и данных назови пропуск в `run_log.md` и проверь конкретную связь.
2. Обновляй снизу вверх: CLM/HYP → ALT → DEC → PRM/EXP. Новую формулировку — новым объектом, старый — `ledger.py supersede`. Если объект попал в список, но по существу не меняется, добавь только `status_note` («проверено по CHG-NNN, без изменений») — так ты сэкономишь и токены, и внимание человека.
3. Начни с ближайших зависимостей из impact. Для дальних проверь, изменился ли их вывод через обновлённые основания. Особо проверь, когда новые данные исправляют прежнюю выгрузку и когда описывают новый период. При изменении ранжирования или решающем противоречии открой нужные разделы и исходные фрагменты.
4. Покажи человеку **diff решения**: для каждого затронутого объекта — было / стало / почему. Для демонстрации удобна цепочка:
   ```
   НОВЫЙ ИСТОЧНИК SRC-…
   ↓ CLM-… уверенность medium → low (противоречит CLM-…)
   ↓ HYP-… ослаблена
   ↓ ALT-… оценка «влияние» 4 → 2
   ↓ DEC-… требует пересмотра
   ```
5. Обновляй затронутые строки на месте. `tools/revise_lines.py projects/<case> --change CHG-NNN` сокращает работу до найденных строк и их оснований при доступном делегировании. Разбери остаток из `verify.py --change CHG-NNN` вручную, включая отклонённые правки. Пометку «проверено по CHG-NNN» ставь после сверки неизменившегося вывода по этому событию. Перед закрытием проверь diff и пустой список устаревших строк.
6. Сохрани `processed: false` до применимых согласований. Если меняется выбор, предъяви дифф на C2. При изменении пакета проверь его через `c3_approval.py prepare` и дождись утверждения предъявленной версии на C3. Проверь дальние затронутые зависимости по графу и ссылкам, если `verify.py --change` их не показывает.
