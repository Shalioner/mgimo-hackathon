# Верификатор утверждений

**Два прохода, чтобы не тратить сотни тысяч токенов.** Замер прогона 2: верификатор-модель, читавший весь пакет, съел около 412K токенов при ~70K на всю остальную работу.

## Проход 1 — код (T0, бесплатно)
```bash
python tools/verify.py projects/<case> --files 03 04 05 06 07 --sample 8
```
Код построчно проверяет `outputs/`:
- `unsupported` — число без ссылки на реестр;
- `wrong-ref` — ссылка на несуществующий объект (код выхода 1);
- `stale-ref` — ссылка на `retracted`/`superseded` (код выхода 1);
- `check` — чисел строки нет в объектах, на которые она ссылается;
- `sample` — N случайных строк «ok» для смысловой выборки.

`wrong-ref` и `stale-ref` исправь сразу сам: это механика.

## Проход 2 — модель (T1), только по списку
Отдай дешёвой модели **только строки из вывода прохода 1** и тексты упомянутых в них объектов (`ledger.py trace <ID>`), а не весь пакет. В Claude Code — субагент `claim-verifier` (haiku). В других средах — `tools/delegate.py --task verify-claims --input <вывод verify.py> --input <нужные куски реестра>`. Если выбрать модель нельзя, выполняй сам, но тоже только по списку.

Для каждой строки вердикт:
- `ok` — подтверждено (число есть в источнике в другой записи, расчёт верен);
- `unsupported` — нет основания: добавить ссылку на CLM/HYP или пометить как допущение;
- `overstated` — формулировка сильнее источника (интерпретация как факт, «главная причина» при low, смена единиц или периода);
- `wrong-ref` — ссылка не на то.

Строки `sample` проверяются только на `overstated`.
