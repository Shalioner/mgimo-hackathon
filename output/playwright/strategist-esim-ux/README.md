## Что проверить в прототипе eSIM

- **HYP-001.** Показать рядом с оформлением подтверждённые условия старта. На двух версиях одного макета проверить, может ли участник верно пересказать, когда стартует пакет, без открытия подробностей. Считать правильные ответы и открытия подробностей.
- **HYP-002.** Развести кнопку оформления и поддержку. На мобильных размерах и при увеличении текста проверить, что виджеты не перекрывают ни подпись, ни область нажатия. Последний параметр должен быть полностью виден при прокрутке.

Гипотезы открыты. Экран оплаты, итоговая цена, оплата из России, фактическая активация и влияние интерфейса на конверсию не наблюдались. Текст сайта о покупке в ОАЭ не использовался как правовой источник. Для обещаний исходного кейса нужны отдельные проверки. [Текущий статус повторного C3](../../../projects/esim-travel/state/progress.md)

## Как проверяли

Playwright открыл публичную англоязычную страницу в изолированном Chromium с мобильной эмуляцией (360 × 732). Сняты каталог, результат нажатия `Plan Details` у выбранного пакета и область после прокрутки до `Activation`. Ни одна кнопка оформления не нажималась. Отдельный сеанс Antigravity прочитал только три PNG. Запрошен Hydrogen xhigh. В журнале три чтения изображений, исполненная модель хостом не подтверждена. Выводы сверены с кадрами и снимками доступности страницы. Время сеанса от старта до завершения — 25,236 с. Расходы и токены неизвестны.

```sh
case_path=output/playwright/strategist-esim-ux
.venv/bin/python tools/ledger.py validate "$case_path"
.venv/bin/python tools/ledger.py trace "$case_path" HYP-001
.venv/bin/python tools/evidence.py "$case_path"
```

`validate` вернул код 0 на девяти записях. `trace` связал гипотезу с тремя кадрами по локаторам. `evidence.py` оставил числа в кадрах на визуальную сверку. В отдельной копии изменение одного байта первого снимка дало код 1 и ошибку SHA-256 у SRC-001. Исходные файлы eSIM сохранены. Обе гипотезы требуют проверки, решение C2 и повторное C3 остаются в исходном кейсе.
