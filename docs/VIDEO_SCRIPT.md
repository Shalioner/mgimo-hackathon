# Сценарий видео: от запроса до продолжения в другой среде

План монтажа — 9:30. Это инструкция к дневной записи, а не свидетельство уже выполненного переноса или готовности демо. Основа — [официальное ТЗ](TZ_OFFICIAL.md#что-отправить) и [козыри проекта](COMPETITORS.md#3-где-мы-впереди--и-чем-это-доказать).

Записываем один проект по опубликованному брифу МегаФона, только на открытых данных. Для него заранее резервируем путь `projects/megafon-demo`; до появления брифа его не создаём. На C1–C3 отвечает человек. Короткие фразы ниже — закадровый текст; на паузах зритель читает экран. Долгие операции записываем целиком, затем ускоряем: титр «ускорено ×N, говорим, что ускорено», где N заменяем фактическим отношением длительности исходника к кадру. Если материал не помещается, сокращаем показ ожидания, сохраняя видимые действия и остановки человека.

## Чек-лист перед записью

- Шрифт терминала ≥ 16 pt; масштаб редактора и браузера позволяет прочитать ID, цитату и итог стоимости.
- Скрыть `.env` и токены: закрыть такие файлы, панели переменных, историю команд с ключами; проверить имена вкладок и уведомления.
- Закрыть лишние вкладки, отключить уведомления; проверить звук и сделать короткую пробную запись речи.
- Получить бриф, пройти реальный демо-проект; заменить текст запроса в кадре его дословной формулировкой. Подготовить открытые материалы и ответы человека на C1–C3. Учебный кейс не выдавать за демо МегаФона.
- Открыть одну и ту же папку в Codex и Claude Code, проверить работоспособность обеих сред. До первого действия записать время начала для расчёта цены. Если перенос не проходит, исправить причину до записи; конфиг сам по себе не подтверждает перенос.
- Взять ID решения и утверждения из демо, сохранить состояние перед перерывом и сравнить журнал после продолжения. Для возражения показать реальную проверку источника, не инсценировать найденную ошибку.
- T02 в baseline сценария ещё не принята. Перед кадром отчёта дождаться её принятия и интеграции, выполнить генерацию и проверить кликабельный CLM. До этого кадр `report.html` не готов к съёмке.
- Для первых трёх показателей взять цену именно демо из `cost.py`, число реально проверенных сред и результат проверки чисел с определением знаменателя. Не подставлять исторические проценты из другого кейса; `verify.py` — проверка ссылок кодом, не доказательство истинности всех утверждений.
- Сохранить время начала/конца, расходы обоих хостов, ошибки, число вмешательств человека в отчёте прогона. Не запускать одновременно несколько сессий в той же папке: `--cwd` и временной интервал должны выделять демо.
- В монтаже заменить каждый ×N фактическим множителем и оставить произнесённое предупреждение об ускорении; проверить непрерывность таймкодов и итог ≤ 9:30. Скриншоты и публикацию делает человек отдельно.

## Команды для кадров

Все команды — из корня репозитория в терминале macOS; это план дневных действий, ночью их на новом проекте не выполняем. Блоки идут по порядку кадров. `CASE` — согласованное имя будущего демо, а не скрытая настройка. Для переноса используем ту же папку на том же компьютере; время начала сохраняем в переменной терминала, не в секретах.

Перед началом исходной записи (зависимости уже установлены по README):

```bash
CASE=projects/megafon-demo
RUN_START=$(date -u '+%Y-%m-%dT%H:%M:%SZ')
printf 'Начало записи: %s\n' "$RUN_START"
test -x .venv/bin/python
.venv/bin/python tools/ledger.py env
.venv/bin/python tools/ledger.py status
```

Для титра 0:00 сначала снимаем итог после завершения прогона командами кадра 8:30 ниже; при монтаже ставим его в начало. Фактические среду и долю берём из журналов и сохранённой проверки, не вычисляем по числу конфигов.

Кадры 0:30–1:30 — в чате Codex: дословный запрос брифа, затем подтверждение C1; команды после создания брифа агентом:

```bash
test -s "$CASE/outputs/01_brief.md"
cat "$CASE/outputs/01_brief.md"
cat "$CASE/outputs/02_research_plan.md"
.venv/bin/python tools/ledger.py route alternatives --env codex
```

Кадры 2:00–3:30 — после сбора источников агентом. Ввести ID реально показанного утверждения из вывода `brief`:

```bash
.venv/bin/python tools/ledger.py brief "$CASE" SRC CLM
.venv/bin/python tools/ledger.py validate "$CASE"
cat "$CASE/outputs/03_situation.md"
read -r 'CLAIM_ID?ID утверждения из демо (CLM-…): '
.venv/bin/python tools/ledger.py trace "$CASE" "$CLAIM_ID"
cat "$CASE/outputs/04_options.md"
```

Кадры 3:30–5:30 — человек выбирает на C2 в чате; после подготовки пакета вводим ID выбранного решения из `brief`. Gate может обращаться к платной модели: запускает агент в рамках заранее согласованных доступов и бюджета демо, секреты на экране не вводятся.

```bash
.venv/bin/python tools/ledger.py brief "$CASE" DEC
read -r 'DECISION_ID?ID решения из демо (DEC-…): '
.venv/bin/python tools/ledger.py trace "$CASE" "$DECISION_ID"
cat "$CASE/outputs/05_product_strategy.md"
cat "$CASE/outputs/06_comms_strategy.md"
cat "$CASE/outputs/07_validation_plan.md"
.venv/bin/python tools/verify.py "$CASE" --files 03 04 05 06 07 --sample 8
.venv/bin/python tools/decide.py --project "$CASE" --gate "$CASE"/outputs/0[3-7]_*.md --step 7
```

Кадры 5:30–6:30 — после C3 в чате произнести возражение из таблицы. Агент запускает self-audit и проверяет реальное основание; источник открывается по локатору из `trace`:

```bash
cat skills/self-audit/SKILL.md
.venv/bin/python tools/ledger.py trace "$CASE" "$DECISION_ID"
.venv/bin/python tools/ledger.py trace "$CASE" "$CLAIM_ID"
```

Кадры 6:30–8:00 — попросить Codex сохранить точку продолжения, затем проверить файлы и закрыть его чат:

```bash
cat "$CASE/state/progress.md"
tail -n 12 "$CASE/state/run_log.md"
.venv/bin/python tools/ledger.py validate "$CASE"
```

Открыть эту папку в Claude Code через интерфейс среды, новый чат: `Продолжи`. После ответа и выполнения следующего шага (те же команды можно выполнить в прежнем терминале, сохранив его переменные):

```bash
.venv/bin/python tools/ledger.py status
cat "$CASE/state/progress.md"
tail -n 12 "$CASE/state/run_log.md"
.venv/bin/python tools/ledger.py validate "$CASE"
```

Кадр 8:00 — только после интеграции принятой T02. Если `tools/report.py` отсутствует, запись этого кадра откладывается. Команда соответствует контракту T02:

```bash
test -f tools/report.py && .venv/bin/python tools/report.py "$CASE"
test -s "$CASE/outputs/report.html" && open "$CASE/outputs/report.html"
```

Кадр 8:30 — завершить агентные действия, зафиксировать конец интервала и посчитать стоимость. `--project` добавляет делегатов из журнала; `--cwd` и интервал выбирают журналы обеих сред. Если сессия стартовала до `RUN_START`, взять её фактическое начало из журнала, чтобы не потерять входной контекст. Отсутствие доступного журнала — пробел, не нулевая цена. Затем обновить отчёт прогона и пересоздать HTML, чтобы шапка получила итог цены:

```bash
RUN_END=$(date -u '+%Y-%m-%dT%H:%M:%SZ')
.venv/bin/python tools/cost.py --cwd "$PWD" --since "$RUN_START" --until "$RUN_END" --project "$CASE" --write "$CASE"
cat "$CASE/state/cost_report.md"
cat "$CASE/outputs/09_run_report.md"
test -f tools/report.py && .venv/bin/python tools/report.py "$CASE"
```

Кадр 9:00 — открыть [MEASUREMENTS.md](MEASUREMENTS.md) и [DESCRIPTION.md](DESCRIPTION.md#7-заявленные-возможности-и-их-ограничения) в редакторе. Протоколы исторических замеров отделяем от показанного демо.
