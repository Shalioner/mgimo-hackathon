## Контракт

```
python tools/datacheck.py <файл.csv|.xlsx> [--sheet <имя>] [--json] [--sep ,|;|\t]
```

- Только стандартная библиотека + то, что уже в `requirements.txt`. XLSX — только если `openpyxl` уже установлен, иначе понятная ошибка с кодом 2 «XLSX не поддержан без openpyxl, сохраните как CSV».
- Разделитель и кодировка определяются сами (`utf-8`, `utf-8-sig`, `cp1251`; `,` `;` `\t`), можно переопределить.
- Числа в русском формате понимаются: `1 234,5`, `12,3 %`, `1 200 ₽`, `−5` (знак минуса U+2212).
- Найденные проблемы — список `issues`, каждая: `{"type", "column", "rows", "detail"}`, `rows` — номера строк файла (с учётом заголовка, первая строка данных = 2). Типы **строго** такие:
  - `missing` — пустое значение или `NA`, `N/A`, `null`, `-`, `—` в столбце, где остальные значения непустые;
  - `duplicate` — полностью одинаковые строки (`rows` — номера всех копий, кроме первой);
  - `unit_mismatch` — в одном столбце значения с разными единицами: `%` и без `%`; `₽`/`руб` и `$`; `тыс.` и без `тыс.`; `млн` и `млрд`; либо единица в заголовке в скобках (`Выручка (тыс. руб)`) не совпадает с суффиксами значений;
  - `period_gap` — в столбце дат/периодов (заголовок содержит `дата`, `date`, `месяц`, `month`, `период`, `period`, `год`, `year`, `квартал`, `quarter` или значения парсятся как `YYYY-MM`, `YYYY-MM-DD`, `MM.YYYY`, `DD.MM.YYYY`, `2025Q1`, `Q1 2025`) пропущен период при регулярном шаге;
  - `period_duplicate` — один и тот же период встречается дважды при отсутствии других ключевых столбцов-измерений (если есть ещё текстовые столбцы — проверять уникальность пары «период + все текстовые столбцы»);
  - `outlier` — числовое значение дальше 3 межквартильных размахов от квартилей (только если в столбце ≥ 8 чисел);
  - `type_mix` — в столбце, где ≥ 80% значений числа, есть нечисловые непустые значения.
- Также в выводе: `summary` — по столбцу тип (`number|date|text`), число непустых, min/max для чисел, первый/последний период для дат, единица.
- Без `--json` — markdown-сводка по-русски: таблица столбцов, затем проблемы списком «строки 5, 9: пропуск в «Выручка»».
- Код возврата: 0 — проблем нет; 1 — проблемы найдены (это нормальный результат); 2 — файл не читается.

## Тесты (минимум)
Фикстуры по одной на каждый тип проблемы + одна «чистая» (код 0, `issues == []`) + одна в `cp1251` с `;` и русскими числами. Тест на каждый тип проверяет `type`, `column` и `rows`.
