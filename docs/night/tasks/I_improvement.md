# I. Доработка по итогам исследования (автономная, на утреннее решение)

**Роль:** реализатор Sol (effort high), тестер Luna. **Ветка:** `night/I-<номер>-<краткое-имя>`. **Приёмка:** `docs/night/accept/I-<номер>.sh` — пишется **в этой же задаче** (см. ниже), поэтому такие ветки **не сливаются в `night/integration`**: утром их смотрит человек.

Запускает оркестратор по пункту из раздела «Кандидаты на ночную реализацию» свежего `SYNTHESIS.md`. Не больше **3** задач I за ночь.

## Порядок (важно: сначала контракт, потом код)

1. `git switch -c night/I-<номер>-<имя>` от `night/integration`.
2. **Первый коммит — только приёмка:** `docs/night/accept/I-<номер>.sh` по образцу `accept/T04.sh` (подключает `lib.sh`, проверки через `ok/bad`, `finish`). Условия — из черновика в SYNTHESIS.md, можно добавить, нельзя ослабить. На текущем коде скрипт **должен вернуть 1** — проверь и запиши вывод в отчёт.
3. Дальше — реализация. Правила `WORKER_RULES.md` действуют полностью, плюс: только стандартная библиотека или то, что уже в `requirements.txt`; не менять существующие публичные команды `tools/*.py` (только добавлять).
4. Приёмка → 0, `common.sh` → 0 (для этих веток `common.sh` разрешает новый файл `docs/night/accept/I-*.sh` — других правок в `docs/night/accept/` нет).
5. Отчёт `docs/night/reports/I-<номер>.md`: какой пункт SYNTHESIS, какая карточка-основание, что сделано, вывод приёмки до и после.

## Ревью Luna (чек-лист)
- [ ] Первый коммит ветки содержит **только** `accept/I-<номер>.sh`, и в отчёте есть его вывод с кодом 1 до реализации.
- [ ] Приёмка не слабее черновика из SYNTHESIS.md (сравни пункты).
- [ ] `accept/I-<номер>.sh` = 0, `common.sh` = 0.
- [ ] Изменение даёт то, что обещано в SYNTHESIS (одна демонстрационная команда с выводом).
