# S-02: что перенять и в каком порядке

## Главное

Победители и призёры из карточек отделяют сбор данных от синтеза и сохраняют основания: [Apollo](cards/B-manasseh-zw-apollo.md), [RiskWise](cards/B-oh-qi-qi-azure-ai-agent-hackathon-2025.md), [Finance](cards/B-MCP-1st-birthday-finance-portfolio-intelligence-platform.md), [Snowman](cards/B-MCP-1st-birthday-snowman-ai.md).
У нас эти принципы уже есть; полезный остаток исследования — раскрывать неудачи сбора и не сравнивать качество при сменившихся правилах оценки.
Главное действие среди новых предложений: проверить малый журнал исходов сбора, чтобы сбой поиска не превратился в вывод об отсутствии спроса.
Следом — сопоставимость оценок и отрицательные контрольные ответы; всё в существующей папке, без новой платформы.
Уверенность ограничена чтением карточек: польза переноса пока гипотеза, результат испытаний и прирост баллов не заявляются.

### Очередь и отсутствие дублей

[Вердикты](../ideas/verdicts.tsv) одобряют идеи, не доказывают реализацию. Сохраняется очередь [IDEA-003](../ideas/IDEA-003.md) → [IDEA-004](../ideas/IDEA-004.md) → [IDEA-001](../ideas/IDEA-001.md) → [IDEA-005](../ideas/IDEA-005.md) → [IDEA-002](../ideas/IDEA-002.md). Этот синтез её не переставляет; 1 → 2 → 3 — порядок только **среди новых** кандидатов. При одном свободном окне пробовать пункт 1, не строить сразу три инструмента.

Исходы сбора — попытки до регистрации, IDEA-001 — копии сохранённых оснований. Компаратор сравнивает **оценки прогонов**, IDEA-004 — **исправления документов/выбора**, IDEA-002 — чувствительность бизнес-рекомендации к весам. Отрицательные ответы не агрегируют сроки (IDEA-003) и не проверяют пути файлов (IDEA-005). T01 — установка; T02 — HTML; T03 — свод проведённых замеров, не компаратор новых оценок; T04 — таблицы; T05 — сквозная репетиция; T06/T07 — сдача/первый экран. Их не открывать заново. Поиск по смыслу остаётся отложенным по карте критериев.

## Кандидаты на ночную реализацию

Три независимых кандидата из строк 1–3, каждый ≤60 мин ИИ. Это **черновики будущей приёмки**: файлов/команд ещё нет, в S-02 они не запускались. Исполнитель работает только в перечисленной зоне, не меняет существующие проекты и ночные документы. Python stdlib и имеющегося PyYAML достаточно; новых зависимостей, платформ, сетевых, модельных и агентных вызовов нет. Общие тесты будущей реализации — в сериализованном слоте.

Сохранить исправленную границу S-01 из [ревью](../reports/S-01.review.md): scorer проверяет поля/ссылки, не смысл. Кейсы содержат вопрос, выдержки, ожидаемые неизвестные и допустимые refs; ответы — `unknowns`, `conclusions`, `refs`. У неизвестного есть «почему» и «как узнать». Всегда `scope: structural_only`, у каждого результата `semantic_support: not_checked`; `grounded`/`semantic_pass` не присваиваются. Коды 0 — соответствует структурному эталону, 1 — расхождение, 2 — невалидный вход.

   | Команда будущей приёмки | Ожидаемый результат |
