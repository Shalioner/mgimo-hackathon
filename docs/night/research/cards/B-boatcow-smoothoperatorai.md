## Как устроено

Программа собирает у клиента вводные о переезде, отбирает перевозчиков из CSV и формирует для голосового агента план переговоров. LangGraph направляет состояние между чат-, стратегическим, голосовым и аналитическим агентами; Firebase хранит состояние, результаты отбора и транскрипты. В README описаны отдельный backend и React Native frontend, облачный деплой и настройки внешних учётных записей.

## Чем силён (по нашим критериям ТЗ)
- кр.1: ранжирование перевозчиков возвращает rationale отбора, а стратегический узел готовит план переговоров на основе требований клиента — `backend/agents/strategist_agent.py`, `_get_movers_data` и `__call__`.
- кр.2: рабочий процесс разделяет сбор требований, подбор поставщиков, переговоры голосом и анализ транскрипта — `backend/agents/agent_graph.py`, узлы и условные переходы.
- кр.3: репозиторий содержит код приложения, frontend и backend, но демонстрирует развёртываемый сервис — `README.md` и дерево репозитория.
