## Как устроено
Команда разделила образовательные функции на восемь специализированных агентов и связала их оркестратором; это описано в Devpost и проектном README.
Отдельные модули отвечают за оценивание эссе по пяти критериям ENEM, генерацию заданий, контента и учебного плана.
Backend в main.py задаёт ADK Runner с DatabaseSessionService на SQLite и HTTP-маршруты для запуска агента и работы с сессиями.
README описывает фронтенд Next.js, хранение в GCS и OCR через Cloud Vision; сведения о стеке — заявления авторов, не проверка развёртывания.
Публичный исходный код проекта включён в монорепозиторий общего каталога ADK-примеров; отдельного репозитория Edu.AI по открытым поискам не найдено.

## Чем силён (по нашим критериям ТЗ)
- кр.1: ответ для эссе строится на явной рубрике из пяти компетенций, а проект сохраняет оценки и обратную связь — Devpost, разделы “What it does” и “Agents”. Это пример привязки оценки к критерию, не подтверждение качества оценок.
- кр.2: восемь узкоспециализированных ролей сведены оркестратором для полного учебного процесса — README.md, таблица “Multi-Agent System Overview”; для Стратега это свидетельство устройства, а не рекомендация копировать число агентов.
- кр.3: структурированные задачи дают персональный план и учебные материалы по результатам, но проект не согласует продуктовую и коммуникационную стратегии — в прочитанных материалах свидетельств нет.
- кр.4: SQLite-сессия и отслеживание прогресса показывают состояние пользователя во времени — README.md и main.py; экономия и контроль человеком не измерены, подтверждения нет.
