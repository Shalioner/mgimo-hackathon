## Как устроено
README описывает визуальный Blockly-редактор, в котором агент планирует несколько операций, меняет блоки, тестирует и проверяет результат.
`project/chat.py` хранит состояние очередей по сессии, формирует Responses API вызовы и ограничивает последовательность максимум 15 итерациями.
Тот же файл содержит инструкцию требовать анализ, псевдокод и пошаговый план до инструментальных действий; ошибки инструментов возвращаются в цикл модели.
`project/test.py` исполняет сгенерированную логику в отдельном процессе и завершает её после восьми секунд; `unified_server.py` объединяет FastAPI и интерфейсы Gradio.
`project/src/serialization.js` сохраняет Blockly-состояние в браузерном localStorage.

## Чем силён (по нашим критериям ТЗ)
- кр.1: README и `project/chat.py` описывают цикл «план → небольшая правка → проверка ответа инструмента → следующая правка», что помогает итеративно уточнять рабочую логику; подтверждённой привязки выводов к источникам для исследований не найдено.
- кр.2: в `project/chat.py` предусмотрена адаптация к ошибкам операций блока с повторными инструментальными шагами, но содержательно разные варианты и сильные возражения проекта не подтверждены.
- кр.3: проверка и тестирование создаваемого MCP-сервера видны в `project/test.py`; стратегия коммуникаций и план проверки продуктового решения не подтверждены.
