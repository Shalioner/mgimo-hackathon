# IDEA-019: Замечать пересечение групп продуктового эксперимента
- Критерий ТЗ: кр.2
- Цитата ТЗ: «Подходящие качественные и количественные методы, воспроизводимые расчёты, проверка показателей, единиц, периодов и пропусков.»
- Новизна: ни у кого в проверенных [COMPETITORS](../../COMPETITORS.md), [Finance](../research/cards/B-MCP-1st-birthday-finance-portfolio-intelligence-platform.md), [Fighter90 decision skills](../research/cards/A-fighter90-product-decision-skills.md) и [llm-space](../research/cards/B-deer-flow-llm-space.md) не описан такой T0-контроль принадлежности одного обезличенного участника разным группам эксперимента. Это новизна относительно указанных описаний, а не новый статистический метод или утверждение обо всех реализациях.
- Что сделать: расширить существующий `datacheck.py` подкомандой `assignment <csv> --subject <колонка> --arm <колонка> --json`: по одному эксперименту, заданному самим файлом, подсчитать уникальных участников каждой группы и участников в нескольких группах; выводить только номера конфликтующих строк и счётчики, без значений идентификаторов. Пустые subject/arm дают `assignment_unknown`, повтор участника внутри той же группы не увеличивает число участников. В `skills/source-intake/SKILL.md` добавить вызов после обычного datacheck, если пользователь явно принёс обезличенную таблицу назначения групп; пересечения и пропуски переносить в limitations соответствующего CLM перед интерпретацией результата. Старый вызов datacheck по пути файла сохраняется.
- Польза, которую можно измерить: на 6 строках назначения R01→A дважды, R02→A/B, R03→B, R04→B получить 4 уникальных участника и ровно 1 пересечение, с локаторами двух строк R02 и без раскрытия R02. До — различающиеся строки одного участника не являются точными дублями таблицы; после — 1 существующий инструмент выявляет нарушение разделения групп до вывода о результатах эксперимента. Причинность, значимость и реальная независимость людей этим не доказываются.
- ИИ-время: ~40 мин
- Риск: неправильные или нестабильные обезличенные ключи скрывают пересечение; перекрёстный дизайн может намеренно менять группы. Поэтому область — supplied_assignment_only, пересечение означает проверить дизайн, а не автоматически отвергнуть эксперимент. Метод вызывается только для явно заданной единицы назначения, без угадывания личности и без персональных данных; отдельные эксперименты заранее разделяются файлами.
- Зона правок: существующие `tools/datacheck.py`, `skills/source-intake/SKILL.md`, `tests/test_datacheck.py`; новые фикстуры `tests/fixtures/assignment/**` только с вымышленными ключами. Новых инструментов и зависимостей нет.
- Черновик приёмки:
  1. `.venv/bin/python tools/datacheck.py assignment tests/fixtures/assignment/overlap.csv --subject participant_key --arm variant --json` → код 1; unique_subjects=4, overlapping_subjects=1, у A два и у B три участника; показаны две исходные строки конфликта без значений ключей.
  2. `.venv/bin/python tools/datacheck.py assignment tests/fixtures/assignment/disjoint.csv --subject participant_key --arm variant --json` → код 0; пересечений 0, повтор в одной группе не увеличивает размер группы, scope=supplied_assignment_only.
  3. `.venv/bin/python -m pytest -q tests/test_datacheck.py -k assignment_unknown_invalid` → код 0; пустые клетки дают код 1/assignment_unknown без заверения о чистоте групп; отсутствующая колонка и нечитаемый CSV дают код 2; строки с неизвестным ключом не объединяются в одного участника.
  4. `.venv/bin/python -m pytest -q tests/test_datacheck.py -k assignment_privacy_legacy_and_skill` → код 0; stdout/stderr не содержат ключей, вход побайтово сохранён, старый CLI работает, source-intake вызывает подкоманду только на таблице назначения; сеть и LLM не вызываются.
- Почему не дубль: IDEA-008/I-02 сравнивает направления агрегатов и сегментов, IDEA-011 — возраст когорты, IDEA-013 считает позиции реальных собеседников. Здесь нет ни долей удержания, ни зрелости, ни голосования: проверяется пересечение явно заданных экспериментальных групп по ключу назначения. T04 выявляет общие дефекты таблицы, но разные строки subject+arm не равны точным дубликатам. IDEA-007 фиксирует условия EXP во времени, S-03 — исходы сбора/оценки/пробелы; они не вычисляют такое пересечение. Отклонённые расчёты не перенесены под новым названием.
- Тест МегаФона: 1 материалы → картина → план проверки: руководитель замечает смешение групп до решения о запуске продукта · 2 счётчики раскрыты строками, unknown и границы причинности сохранены · 3 подкоманда уже используемого datacheck, вызываемая существующим навыком · 4 6 строк → 4 участника и 1 пересечение, 0 выведенных идентификаторов, 0 внешних вызовов.
