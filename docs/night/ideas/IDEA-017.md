# IDEA-017: Руководитель выбирает отдельные предложенные исправления
- Критерий ТЗ: кр.4
- Цитата ТЗ: «Пользователь видит продвижение, может остановить работу, уточнить задачу и исправить результат.»
- Новизна: есть у [client-kickoff](../research/cards/B-appieschot-client-kickoff-skill.md) подтверждение отдельных выходов; у нас уже есть `revise_lines.py --no-apply`. Дополнение — применение выбранных предложений из сохранённого результата без повторной генерации, по явной просьбе руководителя посмотреть правки до записи. Новизна самого просмотра не заявляется.
- Что сделать: расширить существующий `revise_lines.py`: `--no-apply --export-proposals <json>` сохраняет предложения с ID, относительным путём outputs, точным старым/новым фрагментом и хэшем исходного документа; `--apply-proposals <json> --pick P01,P03` применяет только явно выбранные предложения, без вызова модели. Сначала проверить весь выбранный набор: хэши, единственность старого фрагмента, отсутствие пересечений и допустимость путей; при конфликте не записывать ничего. В `workflows/update-decision.md`, шаг 6, встроить эту ветку только при просьбе «сначала покажи»; после уточнения человек может изменить список P-ID или остановить применение, обычный пересмотр не получает нового обязательного checkpoint.
- Польза, которую можно измерить: на 3 сохранённых предложениях выбор P01,P03 меняет ровно 2 фрагмента, P02 остаётся прежним, повторных модельных вызовов при применении 0. До — --no-apply показывает предложения, но последующий обычный запуск заново обращается к генератору; после — применяются те самые выбранные строки. Человеческий выигрыш времени и денег пока не измерен.
- ИИ-время: ~55 мин
- Риск: текст предложения может быть неверен даже при совпадении хэша; утверждения в реестре исправляются существующим self-audit до правки текста. Конфликт из-за ручного изменения документа требует нового просмотра, не автоматического перезаписывания. Хэш не является подписью или доказательством согласия; межфайловую устойчивость к падению ОС эта версия не гарантирует.
- Зона правок: существующие `tools/revise_lines.py`, `workflows/update-decision.md`, `tests/test_revise_lines.py`; новые фикстуры `tests/fixtures/picked_revisions/**`. Новых tools-файлов нет.
- Черновик приёмки:
  1. `.venv/bin/python -m pytest -q tests/test_revise_lines.py -k picked_revisions_export` → код 0; на подменённом локальном ответе делегата экспорт содержит P01–P03 и исходные хэши, все outputs до и после экспорта совпадают побайтово.
  2. `.venv/bin/python -m pytest -q tests/test_revise_lines.py -k picked_revisions_apply_subset` → код 0; CLI с --apply-proposals и --pick P01,P03 изменяет ровно 2 фрагмента, P02 сохранён; модельные/сетевые вызовы запрещены тестом, реестр не меняется.
  3. `.venv/bin/python -m pytest -q tests/test_revise_lines.py -k picked_revisions_conflict` → код 0; изменённый хэш, отсутствующий ID, неоднозначный фрагмент и пересекающиеся предложения дают код 2 до первой записи, включая случай двух файлов с ошибкой во втором.
  4. `.venv/bin/python -m pytest -q tests/test_revise_lines.py -k picked_revisions_paths_and_workflow` → код 0; выход за outputs, symlink наружу и путь к источнику отвергаются; workflow при явной просьбе вызывает экспорт и выбор, не вводит обязательное согласование каждого пересмотра.
- Почему не дубль: отклонённая IDEA-004 сравнивала две папки ПОСЛЕ изменения и показывала квитанцию; здесь такого сравнения нет — добавляется отсутствующая операция выборочного применения ДО изменения уже показанных предложений в существующем инструменте. IDEA-009 проверяет устаревание вопроса C2, а здесь хэш защищает адресную замену текста и не подтверждает выбор ALT. Остальные IDEA-001–015, T01–T07, I-01/02/03 и S-03 не применяют выбранные P-ID без повторного LLM. Наличие --no-apply проверено по текущему --help и не выдаётся за новую функцию.
- Тест МегаФона: 1 пересмотр стратегии: руководитель уточняет, какие правки принять, либо останавливает запись · 2 основания исправлены прежним процессом, текст не объявляется верным из-за хэша · 3 расширение существующего скрипта и workflow над локальными файлами · 4 из 3 предложений применены ровно 2, 0 повторных вызовов модели и 0 изменений при конфликте входа.
