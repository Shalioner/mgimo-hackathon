# IDEA-005: Проверять сохранённый проект перед переносом
- Критерий ТЗ: кр.3
- Цитата ТЗ: «Сохранённый проект переносится в другую среду разработки и продолжается там.»
- Новизна: закрывает наш пробел из [CRITERIA.md](../../CRITERIA.md), кр.3 «Разные среды» и [COMPETITORS.md §3-A](../../COMPETITORS.md): до живого переноса одного проекта нужна воспроизводимая проверка отсутствия зависимости от старой папки.
- Что сделать: один локальный проверочный сценарий `evals/portability/check.py <project> --json`: проверяет, что локальные SRC.path разрешаются внутри проекта, копирует проект в новую временную папку без следования внешним симлинкам, запускает существующий validate по копии и сравнивает progress, выбранные DEC и хэши материалов. При абсолютном пути, выходе за корень, внешнем симлинке или пропаже материала выдаёт ID и причину, не переписывает ссылку молча. Для URL-источников без локального материала помечает `not_checked`, сеть не использует. Проверка не заявляет доказанный запуск другой модели или IDE.
- Польза, которую можно измерить: фикстура с относительными путями и сохранённым C2 даёт 0 потерянных источников и тот же `chosen` после копирования; 3 дефектные фикстуры выявляют зависимость от абсолютного пути, выход `../` и отсутствующий файл до передачи папки. Измеряем число найденных препятствий, а не объявляем структурную проверку полноценным межсредовым E2E.
- ИИ-время: ~45 мин
- Риск: структурный успех могут выдать за доказанный перенос между средами; JSON явно возвращает `scope: filesystem_only`. Входная папка не меняется, ожидаемые предупреждения validate показываются отдельно от ошибок и не скрываются.
- Зона правок: `evals/portability/check.py`, `evals/portability/README.md`, `tests/test_portability.py`, новые `tests/fixtures/portability/**`.
- Черновик приёмки:
  1. `.venv/bin/python evals/portability/check.py tests/fixtures/portability/relative --json` → код 0; `scope: filesystem_only`, источники доступны из новой абсолютной папки, progress и `chosen` совпали, ошибки validate отсутствуют.
  2. `.venv/bin/python -m pytest -q tests/test_portability.py -k absolute_escape_missing` → код 0; абсолютный путь, выход за корень и отсутствующий файл дают код 1 с нужным SRC-ID, автоматических исправлений 0.
  3. `.venv/bin/python -m pytest -q tests/test_portability.py -k external_symlink_and_read_only` → код 0; внешний симлинк не читается и не копируется, все входные файлы сохранены, сеть и агентные CLI не запускаются.
- Почему не дубль: T01 проверяет установку кода из чистого клона, T05 продолжает один демо-проект в том же worktree после паузы, T06 готовит сценарий видео переноса. Здесь проверяется переносимость материалов и состояния произвольного уже сохранённого проекта, без установки и живого агентного прогона. Остальные IDEA — про основания, веса, очередь и исправления, не файловые зависимости; веток I и старых вердиктов при проверке нет.
- Тест МегаФона: 1 сопровождение: уменьшает риск потери оснований при передаче проекта руководителя в другую среду · 2 сверяет источники и выбор, ничего не подменяет и честно ограничивает область проверки · 3 остаётся папка и проверочный скрипт, без переносного сервиса или нового установщика · 4 0 потерянных SRC в исправной фикстуре, 3 класса препятствий выявлены до передачи.
