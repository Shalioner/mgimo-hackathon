# IDEA-014: Остановить исследование до превышения бюджета
- Критерий ТЗ: кр.4
- Цитата ТЗ: «Руководителю продукта понятно, что делает агент, — он может остановить, уточнить и исправить результат.»
- Новизна: есть у thai1311 предупреждение бюджета на 80% — [COMPETITORS.md §1](../../COMPETITORS.md); у нас переводим ограничение руководителя в локальную проверку остатка перед следующим исследовательским действием. [CRITERIA.md](../../CRITERIA.md) отмечает известные расходы, но там нет проверки допуска следующего шага по заданному пределу. Пункт ✅ не объявляется отсутствующим.
- Что сделать: одна команда `tools/budget_check.py <cost-export.json> --limit-usd B --next-upper-usd U --json` над сохранённым выводом существующего `cost.py --json`: брать total_usd и unpriced, считать известный остаток B−total_usd и прогнозный total_usd+U; равенство пределу допускается, превышение требует `pause_for_budget`. U — явно заданная верхняя оценка человека/агента с меткой assumption, не гарантия стоимости вызова. Непустой unpriced либо пустой отчёт без учтённых вызовов дают `unknown`, не нулевой расход. Выход всегда `scope: supplied_cost_export_only`; один абзац в research-plan предписывает при заданном пользователем денежном пределе перед новым сбором сверить свежий экспорт и при pause/unknown показать остаток и остановиться до уточнения. Команда сама ничего не запускает и не завершает процессы.
- Польза, которую можно измерить: при пределе $1, известном расходе $0,90 и верхней оценке следующего шага $0,20 — ровно один сигнал паузы до нового вызова; при $0,10 — допускается только по переданным числам. До — стоимость видна постфактум, после — 1 T0-проверка позволяет руководителю остановить исследование или уменьшить объём. Предотвращённый реальный перерасход до прогона агента не заявляется.
- ИИ-время: ~40 мин
- Риск: неполный или старый экспорт и заниженная U дают ложное ощущение запаса. В JSON и пояснении обязательны исходный предел, известная сумма, оценка U, область supplied_cost_export_only; метки «полная стоимость», «гарантированно уложимся» запрещены. Этот инструмент не учитывает скрытые расходы сервисов и не заменяет cost.py.
- Зона правок: `tools/budget_check.py`, `tests/test_budget_check.py`, новые `tests/fixtures/budget_check/**`, один абзац в `skills/research-plan/SKILL.md` о проверке при уже заданном денежном пределе.
- Черновик приёмки:
  1. `.venv/bin/python tools/budget_check.py tests/fixtures/budget_check/spent090.json --limit-usd 1 --next-upper-usd 0.20 --json` → код 1; pause_for_budget, известный остаток 0.10, прогнозная сумма 1.10, U помечена assumption, scope указан.
  2. `.venv/bin/python tools/budget_check.py tests/fixtures/budget_check/spent090.json --limit-usd 1 --next-upper-usd 0.10 --json` → код 0; within_supplied_estimate, сумма ровно 1.00 считается допустимой, нет обещания фактической цены вызова.
  3. `.venv/bin/python -m pytest -q tests/test_budget_check.py -k unknown_and_invalid` → код 0; unpriced и отчёт без вызовов дают код 1/unknown; отсутствующие поля, отрицательные числа, NaN/Infinity, неверный JSON дают код 2; неизвестная стоимость не превращается в ноль.
  4. `.venv/bin/python -m pytest -q tests/test_budget_check.py -k read_only_no_execution_and_decimal` → код 0; денежная граница проверяется десятичной арифметикой, вход неизменен, ни cost.py, ни агентные CLI, ни сеть/модели не запускаются; обязательные scope и assumption сохранены.
- Почему не дубль: T03 собирает исторические замеры, cost.py считает состоявшиеся расходы; здесь проверяется допустимость следующего шага по явному денежному ограничению руководителя. IDEA-003/I-01 сортирует решения по срокам/статусам, IDEA-010 отбирает основания ALT, IDEA-009 сохраняет версию вопроса C2. T01–T07, I-02, прочие IDEA и S-02 не сравнивают остаток с верхней оценкой следующего действия. Новых обязательных checkpoint C1–C3 не вводим; действует уже заданное ограничение пользователя.
- Тест МегаФона: 1 запрос → исследование: руководитель может остановить расход, снизить объём или уточнить бюджет до следующего шага · 2 известные деньги отделены от оценки, неполнота раскрыта, факты и решения не меняются · 3 локальная проверка файла и короткая инструкция, без биллингового сервиса и фонового контроля · 4 0.90+0.20 при пределе 1 даёт паузу, 0.90+0.10 — граничный допуск, неполные цены — unknown.
