# IDEA-010: Уточнять допущения именно выбранного варианта
- Критерий ТЗ: кр.4
- Цитата ТЗ: «Руководителю продукта понятно, что делает агент, — он может остановить, уточнить и исправить результат.»
- Новизна: закрывает уточнение к удобству из [CRITERIA.md](../../CRITERIA.md), кр.4: trace показывает все основания, но отдельной короткой выборки непроверенных допущений целевого варианта для уточнения руководителем среди инструментов нет. Счётчик скрытых допущений у Fighter90 описан в [COMPETITORS.md §4](../../COMPETITORS.md); здесь отбор по существующим записям, без выдумывания новых скрытых предположений моделью.
- Что сделать: один отчёт `tools/assumptions.py <project> --decision DEC-NNN --alternative ALT-NNN --json`: проверить вхождение ALT в DEC.options, обойти только основания этого ALT и вывести активные HYP без verdict supported/refuted, если `kind: assumption` или `would_change_decision: true`. Для каждого показать точную формулировку, путь от ALT, существующие проверяющие EXP и состояние «эксперимент не задан / результата ещё нет / результат записан, вердикт не внесён». Один HYP по нескольким путям выводится один раз; информация отсутствует — показать «неизвестно», ничего не сочинять и не менять. Вариант задаётся явно и подписывается как выбранный, рекомендованный либо другой кандидат по существующему DEC.
- Польза, которую можно измерить: до — руководитель отделяет допущения своего варианта от полного trace вручную; после — на фикстуре из 6 HYP команда выдаёт ровно 2 подходящих непроверенных основания целевого ALT, 0 гипотез соседнего варианта и 0 дублей. Каждое основание сразу можно назвать агенту по ID для уточнения или остановки дальнейшей разработки; реальное сокращение времени руководителя до пользовательского замера не заявляется.
- ИИ-время: ~40 мин
- Риск: отсутствие verdict не означает ложность гипотезы, а наличие supported не доказывает качество проверки; отчёт описывает только состояние реестра. Допущение без would_change_decision всё равно включается, чтобы не спрятать оценку сроков или ресурсов; неоформленные в реестре предположения обнаружить невозможно.
- Зона правок: `tools/assumptions.py`, `tests/test_assumptions.py`, новые `tests/fixtures/assumptions/**`.
- Черновик приёмки:
  1. `.venv/bin/python tools/assumptions.py tests/fixtures/assumptions/selected --decision DEC-001 --alternative ALT-001 --json` → код 0; из 6 HYP ровно 2 непроверенных основания, все с точной формулировкой и путём от ALT-001, чужая ветка отсутствует.
  2. `.venv/bin/python -m pytest -q tests/test_assumptions.py -k verdict_kind_dedup_and_cycles` → код 0; supported/refuted и неактивные записи не входят в этот список, assumption без would_change_decision входит, повторные пути не дублируют HYP, циклические ссылки дают код 2 с диагностикой.
  3. `.venv/bin/python -m pytest -q tests/test_assumptions.py -k experiment_states_and_choice_label` → код 0; различаются отсутствие EXP, пустой result и результат без verdict; рекомендованный и выбранный ALT подписаны по DEC, команда сама ничего не выбирает.
  4. `.venv/bin/python -m pytest -q tests/test_assumptions.py -k invalid_unknown_read_only_offline` → код 0; ALT вне options и отсутствующий ID дают код 2, неполные данные обозначены неизвестными, хэши реестра сохранены, сетевых и модельных вызовов 0.
- Почему не дубль: IDEA-003/I-01 собирает действия по датам, needs_review и CHG, а здесь без срока и без нового события показаны непроверенные основания ровно одного варианта, в том числе на C2. IDEA-001 считает файлы, 002 меняет веса оценок, 004 сравнивает результаты, 005 проверяет перенос. T05 использует trace в демо, но не выделяет допущения целевого варианта; SYNTHESIS предлагает ширину исследовательских вопросов и контракт неудачного сбора, не этот отбор. IDEA-006 касается PRM, а не вопросов руководителю о риске выбора.
- Тест МегаФона: 1 варианты → стратегия: руководитель видит конкретные основания, которые может уточнить, прежде чем продолжать · 2 только существующие HYP/EXP и пути, непроверенное не превращается в факт или автоматический отказ от варианта · 3 локальный отчёт по реестру в папке, без нового агента и платформы · 4 6 HYP → ровно 2 относящихся к варианту основания, 0 чужих и повторных записей.
