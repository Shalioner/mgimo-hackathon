# IDEA-015: Показывать порог окупаемости выбранного варианта
- Критерий ТЗ: кр.1
- Цитата ТЗ: «Продуктовая — аудитория и её задача, альтернативы, выбранное направление и осознанные отказы, связь пользы с затратами и доходами.»
- Новизна: есть у Fighter90 общие расчёты `pfs calc` и Excel — [COMPETITORS.md §4](../../COMPETITORS.md), у [Finance](../research/cards/B-MCP-1st-birthday-finance-portfolio-intelligence-platform.md) количественный этап перед синтезом. Здесь узкий расчёт порога без зависимости от их приложений; новизна алгоритма не заявляется.
- Что сделать: один калькулятор `tools/break_even.py <project> <scenario.yaml> --json` для одного явно названного ALT: `net_revenue_per_sale`, `variable_cost_per_sale`, `fixed_cost_per_period` в одной явно заданной валюте и периоде, каждое значение с активным CLM/HYP и видом fact|assumption|hypothesis. Рассчитать вклад одной продажи R−V и минимальное целое число продаж ceil(F/(R−V)); при R−V≤0 и F>0 вернуть no_finite_break_even, при F=0 и положительном вкладе — 0. Пустое число — unknown без расчёта, нулевое/отрицательное значение вклада с F=0 — отдельное nonpositive_margin без совета масштабировать. Заявленный выбранным ALT сверять с DEC.chosen, иные ALT явно подписывать как сценарий; записи не менять. Модель линейная, без прогноза спроса, налоговой или инвестиционной рекомендации.
- Польза, которую можно измерить: при R=100, V=60, F=1000 порог равен 25 продажам за указанный период; при F=1001 — 26, без округления вниз. До — таблица пользы/затрат в 05 не даёт воспроизводимого минимального объёма; после — 1 команда связывает порог и каждое исходное число с реестром. Достижимость 25 продаж не выводится из формулы и остаётся отдельной гипотезой.
- ИИ-время: ~45 мин
- Риск: постоянный вклад на продажу и неизменные фиксированные расходы могут быть неверны. Отчёт содержит linear_model_assumption и явные период/валюту/refs; разные валюты, разные периоды фиксированных расходов и смешение выручки с денежным потоком не пересчитываются автоматически. Наличие ref не доказывает смысловую корректность числа; semantic_support=not_checked.
- Зона правок: `tools/break_even.py`, `tests/test_break_even.py`, новые `tests/fixtures/break_even/**`.
- Черновик приёмки:
  1. `.venv/bin/python tools/break_even.py tests/fixtures/break_even/project tests/fixtures/break_even/base.yaml --json` → код 0; вклад 40, порог 25 за заданный период, ALT и все CLM/HYP показаны, linear_model_assumption и semantic_support=not_checked обязательны.
  2. `.venv/bin/python -m pytest -q tests/test_break_even.py -k ceiling_zero_and_nonpositive` → код 0; F=1001 даёт 26, F=0 при положительном вкладе даёт 0; неположительный вклад с F>0 даёт код 1/no_finite_break_even, с F=0 — код 1/nonpositive_margin без совета масштабировать.
  3. `.venv/bin/python -m pytest -q tests/test_break_even.py -k missing_units_refs_and_choice` → код 0; отсутствующая оценка даёт код 1/unknown и никакого порога; смешанные валюты/периоды, отрицательный расход, NaN/Infinity, неизвестный/отозванный ref и ложная метка выбранного ALT дают код 2.
  4. `.venv/bin/python -m pytest -q tests/test_break_even.py -k read_only_offline_and_limits` → код 0; входы и chosen неизменны, внешних вызовов нет, прогноз спроса/вероятность успеха не генерируются, точная десятичная арифметика сохраняет округление вверх.
- Почему не дубль: T04 проверяет качество исходной таблицы, S-02 требует формулы/локатора у CLM, но не задаёт конкретный порог продаж. IDEA-002 сравнивает оценки ALT при разных весах, IDEA-012 проверяет общий ресурс нескольких DEC, а здесь одна линейная модель доходов/расходов одного ALT. T01–T07, I-01/I-02 и IDEA-001–010 не вычисляют безубыточный объём. Это один ограниченный расчёт, не новая финансовая система.
- Тест МегаФона: 1 варианты → стратегия: руководитель видит объём продаж, который требуется для покрытия заданных затрат · 2 каждое число связано с CLM/HYP, допущение линейности и неизвестный спрос видны · 3 калькулятор и YAML в папке, без финансовой платформы, ключей и новых библиотек · 4 контрольные пороги 25 и 26 воспроизводимы, неположительный вклад и пробелы не порождают выдуманной окупаемости.
