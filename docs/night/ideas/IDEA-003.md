# IDEA-003: Одна очередь решений на сегодня
- Критерий ТЗ: кр.4
- Цитата ТЗ: «Руководителю продукта понятно, что делает агент, — он может остановить, уточнить и исправить результат.»
- Новизна: закрывает наш пробел из [CRITERIA.md](../../CRITERIA.md), кр.2: нет команды «что решать сейчас / какие основания устарели»; идея делает существующее правило навыка decision-support воспроизводимым.
- Что сделать: одна команда `tools/next.py <project> --on YYYY-MM-DD --json`: собрать DEC с `needs_review`, DEC с наступившим `review_by`, CHG с `processed: false` и ссылки этих решений на отозванные/заменённые основания. Объединять причины по DEC, сортировать детерминированно, выводить ID, причину, дату и следующее действие человека; не вычислять бизнес-приоритет без данных и ничего не менять. Дату можно задавать для воспроизводимости, по умолчанию сегодня.
- Польза, которую можно измерить: вместо ручного сопоставления progress, решений и изменений — 1 команда; фикстура с просроченным DEC, DEC needs_review и необработанным CHG выдаёт ровно 3 пункта, без двойного счёта нескольких причин одного решения. Дата и причины проверяются кодом, ручная классификация моделью не требуется.
- ИИ-время: ~35 мин
- Риск: очередь могут принять за разрешение автоматически пересмотреть выбор; формулировки требуют действия руководителя, `chosen` и C2 сохраняются. Для экспериментов без однозначной даты окончания срок не угадывается; они не входят в первую версию.
- Зона правок: `tools/next.py`, `tests/test_next.py`, новые `tests/fixtures/next/**`, `skills/decision-support/SKILL.md` — одна строка вызова в существующем пункте «Что решать сейчас».
- Черновик приёмки:
  1. `.venv/bin/python tools/next.py tests/fixtures/next/actionable --on 2026-11-12 --json` → код 0; ровно 3 пункта, каждый с ID и причиной, `review_by` в день проверки считается наступившим.
  2. `.venv/bin/python -m pytest -q tests/test_next.py -k future_processed_and_dedup` → код 0; будущий срок и обработанный CHG не попадают в очередь, две причины одного DEC дают один пункт с двумя причинами.
  3. `.venv/bin/python -m pytest -q tests/test_next.py -k read_only_and_reproducible` → код 0; два вызова с одной датой дают одинаковый JSON, хэши файлов проекта не меняются, внешних вызовов 0.
- Почему не дубль: status показывает шаг, trace раскрывает одно основание, impact требует конкретного CHG; ни один не собирает общую датированную очередь для руководителя. Существующий навык описывает её словами — новая команда исполняет это правило. T01–T07 занимаются запуском, упаковкой, замерами, данными и демо; другие IDEA не агрегируют действия по срокам. Ветки I и прежние вердикты при проверке отсутствуют.
- Тест МегаФона: 1 сопровождение: руководитель видит, где требуется его уточнение или исправление · 2 каждое действие привязано к реальному ID и полю даты/статуса, нет нового решения от агента · 3 запуск существующей агентной средой над локальной папкой · 4 одна команда, 3 эталонных пункта, 0 дублей и изменений данных.
