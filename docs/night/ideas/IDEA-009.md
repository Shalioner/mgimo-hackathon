# IDEA-009: Согласовывать именно показанную версию вариантов
- Критерий ТЗ: кр.3
- Цитата ТЗ: «Работу можно остановить и продолжить с сохранённого места, не начиная заново (в том числе открыв новый чат).»
- Новизна: есть у [llm-space](../research/cards/B-deer-flow-llm-space.md) похожее связывание оценки с версией рубрики; у нас применяем к сохранённому вопросу руководителю на C2. [CRITERIA.md](../../CRITERIA.md) отмечает продолжение ✅, но проверка неизменности показанного пакета во время ожидания отдельно не подтверждена; это уточнение зелёного сценария, а не новый заявленный ❌.
- Что сделать: один инструмент `tools/checkpoint_packet.py capture|check <project> --question <question.md> --packet <file.json> --json`, ограниченный C2: `capture` создаёт новый файл с точным текстом уже подготовленного вопроса и SHA-256 вопроса, `outputs/01_brief.md`, `03_situation.md`, `04_options.md` и всех `state/ledger/*.yaml`; `check` сверяет состав и байты пакета с текущими файлами. Изменился вопрос, вариант или основание — вернуть `stale_question` со списком файлов и потребностью показать обновлённый вопрос. Команда не принимает ответ за человека, не записывает chosen и не отменяет обязательный C2; ответ на старый вопрос не переносится автоматически.
- Польза, которую можно измерить: до — сохранённый вопрос и текущие варианты сверяют вручную после перерыва; после — 1 команда различает неизменный пакет и подмену варианта, правку основания или самого вопроса. Три дефектных фикстуры должны дать `stale_question`, а изменение только run_log/progress — оставить пакет пригодным для того же вопроса; это проверка версии, не доказательство получения согласия.
- ИИ-время: ~45 мин
- Риск: хэш замечает даже косметическую правку, а полный реестр — изменение незатронутого основания; выбран консервативный сигнал повторно показать вопрос. Пакет без подписи не защищён от ручной подделки; сам по себе он не доказывает согласование, качество вариантов или запуск в другой IDE.
- Зона правок: `tools/checkpoint_packet.py`, `tests/test_checkpoint_packet.py`, новые `tests/fixtures/checkpoint_packet/**`.
- Черновик приёмки:
  1. `.venv/bin/python -m pytest -q tests/test_checkpoint_packet.py -k capture_resume_and_progress_only` → код 0; новый пакет создаётся в tmp_path без перезаписи, одинаковый вопрос после перерыва даёт код 0, изменения только progress/run_log не меняют его пригодность, текст вопроса совпадает побайтно.
  2. `.venv/bin/python tools/checkpoint_packet.py check tests/fixtures/checkpoint_packet/changed --question tests/fixtures/checkpoint_packet/question.md --packet tests/fixtures/checkpoint_packet/before.json --json` → код 1; `stale_question: true`, среди причин ровно изменённый `04_options.md`.
  3. `.venv/bin/python -m pytest -q tests/test_checkpoint_packet.py -k question_ledger_addition_and_deletion` → код 0; правка вопроса, изменение YAML, добавление нового YAML или удаление файла пакета обнаружены со своими путями, `chosen` и исходные файлы не изменены.
  4. `.venv/bin/python -m pytest -q tests/test_checkpoint_packet.py -k no_overwrite_invalid_and_offline` → код 0; перезапись, недостающий обязательный вход или невалидный JSON дают код 2, сеть и агентные CLI не запускаются.
- Почему не дубль: T05 проверяет продолжение по progress после уже состоявшегося C2, а здесь перерыв происходит во время ожидания ответа и проверяется версия самого вопроса. IDEA-004 сравнивает две готовые папки с результатами, 005 проверяет зависимости при переносе; ни одна не связывает вопрос C2 с конкретными входами. IDEA-007 сравнивает отдельные условия EXP после измерения, здесь — документы вариантов до человеческого выбора; общего нового механизма согласования не строим. I-01 и SYNTHESIS не проверяют устаревший вопрос.
- Тест МегаФона: 1 варианты → решение после паузы: руководитель не подтверждает незаметно изменившийся набор оснований · 2 вопрос и версии входов сохранены, право выбора человеку, согласие скрипт не выдумывает · 3 JSON и проверка внутри папки, без сервера и скрытой настройки · 4 3 класса подмены выявлены одной командой, изменение журнала не создаёт ложного stale.
