# IDEA-020: Восстановить готовый ответ без повторного вызова
- Критерий ТЗ: кр.3
- Цитата ТЗ: «Ошибки и недоступность инструментов замечаются, работа возобновляется без незаметного повтора выполненных действий.»
- Новизна: есть у [DeerFlow, по SYNTHESIS](../research/SYNTHESIS.md) сохранённые результаты после перезапуска; у нас delegate уже сохраняет ответы в state/delegated. Предлагается узкое восстановление успешно сохранённого результата извлечения, когда ответ есть, а основной агент не успел его использовать. Общий retry или наличие файлов новой функцией не объявляются.
- Что сделать: расширить существующий `delegate.py` режимом `--recover <каталог-запуска>` для задачи extract-claims: при обычном завершении сохранять рядом с ответом завершённый manifest с task, resolved model/effort, SHA-256 точного задания, всех переданных входов и ответа; recover сверяет эти данные с текущими --prompt-file/--input и возвращает прежний ответ только при полном совпадении и успешном статусе. При ошибке восстановления не запускать модель автоматически. В `skills/source-intake/SKILL.md`, раздел экономии, встроить ветку: после перерыва сначала проверить подходящий сохранённый запуск, восстановить его и проверить ответ, затем регистрировать CLM обычным способом. Никаких автоматических записей CLM или бесконечного кеша.
- Польза, которую можно измерить: сценарий «успешный ответ записан → агент прерван до внесения CLM → продолжение» использует 1 исходный модельный вызов вместо 2, при recover новых вызовов 0. Изменение любого входа, задания или ответа даёт объяснимый отказ, а не устаревшие факты. Денежная экономия до фактического прогона и тарификации не посчитана; измеряем счётчик вызовов на подменённом бэкенде.
- ИИ-время: ~55 мин
- Риск: тот же текст задания может зависеть от непереданного контекста; поэтому восстановление только для изолированного extract-claims с явно переданными файлами, результат всё равно проверяется основным агентом. Manifest не удостоверяет смысл ответа, подлинность источника и оплату вызова. Старые ответы без manifest, незавершённые вызовы и неуспешный статус не восстанавливаются. Пути ограничены state/delegated данного проекта.
- Зона правок: существующие `tools/delegate.py`, `skills/source-intake/SKILL.md`; поддерживающие тесты `tests/test_delegate_recovery.py` и новые вымышленные фикстуры `tests/fixtures/delegate_recovery/**`. Новых tools/*.py и зависимостей нет.
- Черновик приёмки:
  1. `.venv/bin/python -m pytest -q tests/test_delegate_recovery.py -k successful_answer_after_interruption` → код 0; подменённый бэкенд вызывается 1 раз для исходного запуска, recover возвращает побайтово тот же ответ с меткой recovered, второй вызов запрещён тестом.
  2. `.venv/bin/python -m pytest -q tests/test_delegate_recovery.py -k changed_inputs_prompt_or_answer` → код 0; по отдельности изменение входного файла, задания, модели/effort или ответа даёт код 2 с причиной и 0 попыток автоматического повтора.
  3. `.venv/bin/python -m pytest -q tests/test_delegate_recovery.py -k incomplete_failed_or_external` → код 0; старый каталог без manifest, оборванный JSON, неуспешный запуск, другая задача и путь/символическая ссылка вне delegated отвергаются; прежние результаты не перезаписываются.
  4. `.venv/bin/python -m pytest -q tests/test_delegate_recovery.py -k no_ledger_write_and_skill_entry` → код 0; CLM и источники не меняются, в run_log восстановление отмечено без повторного учёта первоначального вызова, навык явно ставит recover перед повторной делегацией; реальные сеть/модели/CLI агентов не запускаются.
- Почему не дубль: T01 проверяет установку, IDEA-005 сравнивала целостность переносимой папки; здесь нет проверки переноса или новой среды — восстанавливается уже завершённый платный этап внутри существующего вызова. IDEA-014/I-03 оценивает бюджет будущего действия, но не возвращает сохранённый ответ. IDEA-017 применяет выбранные текстовые правки к outputs; extract-claims здесь только выдаёт прежний материал и никогда не применяет правки. Остальные IDEA, T02–T07, I-01/02 и S-03 не задают условие безопасного повторного использования конкретного результата делегата.
- Тест МегаФона: 1 сбор → картина после перерыва: руководитель получает продолжение без повторного извлечения уже сохранённого материала · 2 ответ совпадает с заданием и входами, основная проверка и SRC/CLM сохраняются · 3 восстановление через существующие CLI и навык, без сервиса и настройки · 4 сценарий даёт 1 вызов вместо 2, 0 новых вызовов при recover и отказ при каждом изменённом входе.
