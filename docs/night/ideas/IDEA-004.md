# IDEA-004: Квитанция исправлений для руководителя продукта
- Критерий ТЗ: кр.4
- Цитата ТЗ: «Пользователь видит продвижение, может остановить работу, уточнить задачу и исправить результат.»
- Новизна: закрывает наш пробел в сценарии удобства из [CRITERIA.md](../../CRITERIA.md), кр.4: строка исправления отмечена ✅ по E2E, но отдельного сравнения результатов до/после среди инструментов нет. Это выявленное уточнение к зелёной строке, а не приписанный таблице статус ❌.
- Что сделать: один отчёт `tools/result_diff.py <before-project> <after-project> --json` по сохранённым папкам: показать только изменённые абзацы `outputs/01–08`, документ, старый/новый текст и ID из обоих текстов; отдельно вынести изменения `recommended`, `chosen` и `decided_by` существующих DEC. Исходные папки только читаются, старую версию передают явно, при её отсутствии команда сообщает ошибку, не восстанавливает историю догадкой.
- Польза, которую можно измерить: на фикстуре из 8 документов, где исправлены 2 абзаца в 2 документах, отчёт содержит ровно 2 изменения и 0 неизменённых абзацев. Отдельный тест показывает изменение человеческого выбора даже при неизменном Markdown; руководитель проверяет объём своей правки одним отчётом.
- ИИ-время: ~45 мин
- Риск: смена переносов строк может раздуть diff; абзацы сравниваются после нормализации переносов внутри абзаца, но числа, знаки и ID не нормализуются. Отчёт фиксирует изменение текста, не доказывает его качество и не объявляет изменение `chosen` согласованным.
- Зона правок: `tools/result_diff.py`, `tests/test_result_diff.py`, новые `tests/fixtures/result_diff/**`.
- Черновик приёмки:
  1. `.venv/bin/python tools/result_diff.py tests/fixtures/result_diff/before tests/fixtures/result_diff/after --json` → код 0; ровно 2 изменённых абзаца, правильные имена документов, старые и новые CLM-ID сохранены.
  2. `.venv/bin/python -m pytest -q tests/test_result_diff.py -k choice_and_deletion` → код 0; изменение `chosen` видно отдельным полем, удалённый абзац выведен со старым текстом, добавленный — с новым.
  3. `.venv/bin/python -m pytest -q tests/test_result_diff.py -k wrapping_missing_and_read_only` → код 0; один перенос внутри абзаца даёт 0 изменений, отсутствующая старая папка — код 2, входные папки побайтово сохранены.
- Почему не дубль: T02 объединяет текущие документы в HTML, но не сравнивает версии; revise_lines обновляет затронутые строки, а self-audit ищет ошибочное основание. Здесь отдельная проверка руководителем, что именно поменялось после его поправки, включая человеческий выбор; это не новый механизм пересмотра. T01–T07 и IDEA-001–003/005 не выдают такого сравнения. Прежних вердиктов и веток I при проверке нет.
- Тест МегаФона: 1 сопровождение → исправленная стратегия: руководитель проверяет результат своей поправки · 2 старые и новые основания видны одновременно, смена человеческого решения не прячется · 3 отчёт по двум папкам, без UI, фонового процесса и внешней отправки · 4 на 8 документах выделены ровно 2 исправления, перенос строки не создаёт ложное изменение.
