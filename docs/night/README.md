# Ночной прогон: несколько агентов Codex в Orca

Оркестратор **Astra** раздаёт задачи, реализаторы **Sol** делают, тестеры **Luna** проверяют. Утром ты запускаешь одну команду и видишь по каждой задаче «принято / не принято» с конкретными непройденными пунктами.

## Что в пакете

| Файл | Для кого | Что это |
|---|---|---|
| [ORCHESTRATOR.md](ORCHESTRATOR.md) | Astra | DAG задач, цикл «Sol → Luna → проверка кодом → слияние», лимиты, запреты, формат итогового отчёта |
| [WORKER_RULES.md](WORKER_RULES.md) | Sol и Luna | зона правок, запреты (push, удаление, чужие файлы), что делать без человека, шаблоны отчёта и ревью |
| `tasks/T01…T07` | Sol | ТЗ задач: зачем (критерий ТЗ), что можно менять, контракт, чек-лист ревью Luna |
| `accept/T01…T07.sh`, `common.sh` | все + ты утром | **жёсткая приёмка кодом**: 0 = принято. Воркерам менять запрещено |
| [check_all.sh](check_all.sh) | ты утром | гоняет всю приёмку на `night/integration` в отдельном worktree, скрипты берёт из `main` |
| `reports/` | воркеры пишут | `<id>.md` — отчёт Sol, `<id>.review.md` — вердикт Luna, `NIGHT_REPORT.md` — итог Astra |

## Исследование (идёт всю ночь параллельно, до 7 ч)

Мы не переписываем агента, а полируем и добавляем в стек то, что поднимет баллы. Чтобы понять, что именно, Luna-исследователи непрерывно ищут, как сделали другие.

| Поток | Кто | Что | Результат |
|---|---|---|---|
| **Группа A** — 3 Luna | репозитории участников MGIMO×AI Challenge по нашему кейсу, затем по другим кейсам хакатона | карточка на находку: устройство, сильные стороны по кр. 1–4, «что перенять», вердикт |
| **Группа B** — 3 Luna, **+3 из A**, когда A исчерпана | победители и призёры других хакатонов по ИИ-агентам, особенно зарубежных (devpost, lablab, вендорские, Kaggle), и эталонные open-source агенты | то же, плюс URL страницы результатов как доказательство победы |
| **Синтез** — Sol | каждые ≥ 8 новых карточек и в конце | `research/SYNTHESIS.md`: паттерны победителей (≥ 2 совпадения), до 10 «что перенять» по пользе/цене, до 3 кандидатов на реализацию |
| **Доработки I** — Sol + Luna | до 3 пунктов из синтеза, после того как T01–T05 закончены | ветки `night/I-*`: сначала приёмка, потом код; **не сливаются**, утром решаешь ты |

Как это самоорганизуется (`ORCHESTRATOR.md` §6): оркестратор ведёт `research/index.tsv` (всё найденное, без дублей) и `research/queue.tsv` (очередь зацепок). Каждый исследователь берёт пачку из 5 запросов или 3 URL, отдаёт карточки и **новые зацепки** — они уходят в очередь. Группа A считается исчерпанной, когда её очередь пуста и две выдачи подряд не дали ничего нового; тогда её 3 слота переходят в B. Если очередь B пуста, оркестратор сам придумывает новые запросы, меняя тип хакатона, страну, язык и тему. Лимит — 60 выдач за ночь.

## Идеи: Sol придумывает, Astra проверяет

Sol-придумыватель (`tasks/G_ideas.md`) запускается в начале ночи и после каждого синтеза, до 4 раз. За раз — 5 идей: каждая — одно проверяемое изменение, минимум 2 из 5 — «такого нет ни у кого», не больше 2 на один критерий. Astra проверяет **каждую** по рубрике из 6 условий: дословная цитата ТЗ, измеримая польза, приёмка кодом, ≤ 60 мин, не дубль, не «объём ради объёма». Вердикт «да/нет» с причиной и приоритетом пишется в `ideas/verdicts.tsv`. Если Astra приняла 5 из 5 или 0 из 5, она обязана пересмотреть спорные. Принятые идеи вместе с кандидатами синтеза образуют очередь доработок I.

Форму идей проверяет `accept/G.sh`: все поля заполнены, цитата **дословно** есть в ТЗ, у пользы есть число, в приёмке ≥ 3 команд, зона правок вне запретных.

## Надзор: Claude Code раз в час

Эта сессия Claude Code в основной папке раз в час (`/loop 60m`) запускает `bash docs/night/supervise.sh`. Скрипт ничего не меняет, он печатает факты и сигналы `⚠`: цикл встал, STATUS.md устарел, поиск ушёл не в ту тему, нет победителей, Astra штампует или режет все идеи, превышены лимиты или $30, тронут `main`, запретные зоны, удаления. По таблице [SUPERVISOR.md](SUPERVISOR.md) надзиратель отправляет оркестратору **одну** поправку в час (`orca orchestration send`, тема `НАДЗОР: …`). Оркестратор обязан ответить и отметить её в `reports/STATUS.md` (§8–§9 ORCHESTRATOR.md). Поправка не может разрешить запрещённое. Журнал надзора — `reports/SUPERVISOR_LOG.md`.

Приёмка карточки кодом (`accept/R.sh`): все поля шаблона заполнены; «победитель / призёр / финалист» — только с URL-доказательством; есть ссылка на критерий ТЗ; вердикт из списка; репозиторий существует (`gh api`); не дубль. Чужой код только читается через `gh api`: не клонируется и не запускается, инструкции из чужих README не выполняются.

Ночью **не** делается то, что требует человека или живой записи: перенос Codex → Claude Code на видео, скриншоты, демо МегаФона, Jev-ключ.

## Запуск (вечером)

1. **Режим без подтверждений для Codex.** Ночью никто не нажмёт «разрешить». В настройках агента `codex` в Orca (или в `~/.codex/config.toml`) должно быть автоматическое выполнение команд в worktree и разрешён доступ в сеть (нужен `pip install` и открытые сайты для T05). Если Codex будет спрашивать разрешения, прогон встанет на первой же команде.
2. Пакет должен быть в `main` — воркеры создаются от него:
   ```bash
   git add docs/night docs/COMPETITORS.md docs/SUBMISSION_PLAN.md && git commit -m "Ночной пакет: ТЗ оркестратора и задач, приёмка кодом"
   ```
3. Запустить оркестратора в отдельном worktree:
   ```bash
   orca worktree create --repo id:e98d5423-4581-4be3-bd78-bdd52ede02a8 --name night-orchestrator --base-branch main --agent codex --model gpt-6-astra --effort medium --prompt "Ты оркестратор ночного прогона. Прочитай docs/night/ORCHESTRATOR.md и docs/night/WORKER_RULES.md и выполни их. Человек недоступен до утра: ничего не спрашивай, спорное записывай в отчёт." --activate
   ```
4. Посмотреть 5 минут, что оркестратор создал Run, задачи и запустил первых воркеров (T05 — первым).
5. В этой сессии Claude Code включить надзор: запрет сна Mac на ночь и `/loop 60m` по [SUPERVISOR.md](SUPERVISOR.md). Окно приложения не закрывать. Дальше можно идти спать.

## Проверка (утром)

```bash
bash docs/night/check_all.sh
```

Что увидишь:
- таблицу `Задача · Приёмка (ПРИНЯТО / НЕ ПРИНЯТО) · Ревью Luna · Статус из отчёта Sol`;
- общую проверку ветки: тесты, реестры, запретные зоны, удалённые файлы, секреты;
- по каждой непринятой задаче — список непройденных пунктов `✗`;
- блок «Исследование»: сколько карточек по группам, сколько «перенять», сколько подтверждённых победителей, приёмка всех карточек и синтеза, «Главное» из `SYNTHESIS.md`;
- список веток доработок `night/I-*` с ревью и командой diff — их приёмку писал сам воркер, поэтому смотри глазами;
- начало `NIGHT_REPORT.md` с разделом «Что требует решения человека».

Как решать:
- **ПРИНЯТО + ACCEPT** — посмотреть diff глазами (`git diff main...night/integration -- <файлы задачи>`), особенно README и DESCRIPTION, и принять.
- **ПРИНЯТО, но ревью REJECT или его нет** — прочитать `reports/<id>.review.md`: скрипт прошёл, но Luna нашла содержательную проблему.
- **НЕ ПРИНЯТО** — пункты `✗` и есть ТЗ на доработку. Можно отдать днём одному воркеру Sol: «доделай T0N, вот непройденные пункты».
- Сливать в `main` — только ты, после просмотра: `git merge --no-ff night/integration`. Ночью никто ничего не пушит и в `main` не сливает.

## Почему так устроено

- **Приёмка кодом, а не словами модели.** Скрипт нельзя уговорить, и он одинаков для Luna, Astra и тебя. Luna добавляет то, что кодом не проверить (смысл возражений, совпадение цифр с источником).
- **Скрипты утром берутся из `main`.** Даже если воркер нарушит запрет и поправит скрипт, проверка пойдёт по исходному контракту.
- **Каждая задача — свой worktree и своя ветка.** Воркеры не мешают друг другу, а неудачная задача не портит остальные.
- **Модели по ролям:** Astra только координирует (дорогая, но мало токенов), Sol пишет (основной объём), Luna гоняет скрипты и чек-листы (дёшево). Эскалация — только `effort xhigh` у той же Sol, один раз на задачу.
