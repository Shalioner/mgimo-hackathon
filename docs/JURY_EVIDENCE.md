## Быстрый путь проверки: команды и 36 офлайн-проверок

Для проверки комплекта жюри **не нужны** API-ключи, доступ к моделям, локальный классификатор D1 или история Git. Всё ниже выполняется локально из корня репозитория или распакованного архива (Python 3.9+, macOS/Linux/WSL):

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python evals/score9/jury/run.py
```

Чтобы получить полный журнал всех 36 команд с кодами выхода и stdout, добавьте флаг `--json`.

В Windows создайте окружение через `py -m venv .venv` и используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Сценарий жюри передаёт дочерним командам путь текущего Python. Полная проверка поставки выполнена на macOS.

Точечные команды для чтения и проверки:

```sh
# Сводка по всем проектам и текущему шагу
.venv/bin/python tools/ledger.py status

# Восстановление официального кейса: выбранный ALT-003, квитанция C3, ближайшее действие
.venv/bin/python tools/next.py projects/family-connect --resume
.venv/bin/python tools/c3_approval.py check projects/family-connect --json
.venv/bin/python tools/ledger.py trace projects/family-connect DEC-001

# Кейс с открытым повторным C3 и каскадом влияния новых сведений
.venv/bin/python tools/next.py projects/esim-travel --resume
.venv/bin/python tools/ledger.py impact projects/esim-travel CHG-001

# Портируемые CLI-контроли пересмотра после C3 (на временной копии, без записи в репозиторий)
.venv/bin/python evals/score9/factory-experiments/post-c3/reproduce_cli.py --candidate .

# Полный набор автотестов (в чистой распаковке: 1 552 passed, 1 skipped)
.venv/bin/python -m pytest -q tests
```

### Что именно проверяют 36 команд `evals/score9/jury/run.py`

Скрипт [evals/score9/jury/run.py](../evals/score9/jury/run.py) копирует поставку во временный каталог, выполняет **36 офлайн-команд** (34 вызова CLI + 2 вызова хуков, `model_calls: 0`) и сверяет SHA-256 всех файлов исходных кейсов до и после запуска (`family-connect`, `esim-travel`, `rehearsal-mobile-spend` остаются побайтно неизменными):

**Граница офлайн-проверки.** 36 команд и `pytest` проверяют схемы, трассировку, блокировки C3, повтор записи квитанции, восстановление состояния (`--resume`) и сохранность исходных кейсов. Для проверки используется готовый учебный бриф C1. Отдельный живой эксперимент проверил изменение пакета и возврат в новый чат. Активное время руководителя, полная стоимость и полевой эффект остаются без измерения. [Живой прогон](../evals/score9/factory-experiments/post-c3/LIVE_REVISION.md) · [Запросы и ответы](../evals/score9/factory-experiments/post-c3/LIVE_REVISION_RESPONSES.md)

**Основной путь vs опциональная маршрутизация.** Весь описанный выше контур и официальный кейс работают без локального классификатора D1, MCP и внешних API — для живого диалога достаточно одной модели вашей IDE. Подключение D1/MCP/дополнительных провайдеров вынесено в опциональный контур и не требуется для проверки поставки. [Архитектура и границы контуров](DESCRIPTION.md#архитектура-модели-и-инструменты) · [Дополнительные интеграции](ROUTING_ADVANCED.md).

## Повторное открытие кейса до C3

21 ноября в две отдельные сессии Codex GPT-6.1 Sol передали реплику «Продолжи кейс “Связь для близких” по сохранённому состоянию». Первая открыла папку из архива без истории Git, восстановила DEC-001 / ALT-003 и дошла до открытого C3. Она опустила SHA-256. После уточнения точки продолжения повтор из рабочей папки показал пятичастный документ и полный SHA-256. В обоих запусках `c3_approval.py check … --json` показал `unrecorded`.
