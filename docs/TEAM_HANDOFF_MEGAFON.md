# Передача сокоманднику: открытые проблемы ИИ-стека «Стратег»

**Дата:** 16 ноября 2026. **Базовый коммит реализации:** `e626b5a`.
**Цель:** проверить интеграции, устранить подтверждённые дефекты и закрыть
оставшиеся проверки перед демонстрацией и корпоративным внедрением.

## Главное

Локальная D1, очередь, точный кэш и компактный native-роутинг реализованы и
проверены на MacBook Air M1 8 ГБ. Мод Claude Code написан и зарегистрирован,
но реальное применение маршрута внутри Claude ещё не подтверждено. Есть
ограничение лицензии модели для крупного бизнеса и синхронное ожидание D1
в Codex app-server. Называть всю систему готовой к промышленному внедрению рано.

Документ различает **дефект**, **незакрытую проверку**, **оптимизацию** и
**условие внедрения**. Отсутствие проверки не означает, что функция сломана.
Приоритеты ниже — порядок работы команды, а не рейтинг уязвимостей.

## С чего начать

1. Получить репозиторий с базовым коммитом и этим документом. Один Markdown
   без исходников не является поставкой. Работать в отдельной ветке.
2. Проверить `git status --short` и сохранить существующие изменения. Не
   использовать общий reset/clean для «очистки» чужой работы.
3. Создать окружение по README; локальные настройки брать из
   `knowledge/routing.local.example.yaml`, не из чужого приватного конфига.
4. Запустить безопасные проверки ниже. Живой запрос в Claude выполняется
   отдельно в разрешённом аккаунте/среде с доступной моделью; он расходует
   ресурсы аккаунта и не входит в офлайн-тесты.

```sh
.venv/bin/python -m pytest -q
node --test plugins/strategist-routing/tests/routing.node.mjs
.venv/bin/python tools/doctor.py doctor --host claude-code
.venv/bin/python tools/install_host_routing.py
```

Последняя команда — план установки без записи. `doctor` не вызывает модель
и не доказывает работу runtime. На новом Mac инструкции для D1:
[D1_MACOS.md](D1_MACOS.md). Зафиксировать версии Python, ОС, Claude/Codex,
model repo/revision, baseline commit и использованный конфиг без секретов.

### MF-01. Коммерческое использование D1

**Факт:** pinned `LiquidAI/d1-2B-MLX-8bit`, revision
`3247d0483b11e5da31fa10e7979c23252fbe3580`, содержит LFM Open License v1.0.
§5 ограничивает коммерческое использование юридическими лицами выше порога
выручки; определение Threshold указывает $10 млн. Локальный LICENSE проверен
по SHA256 manifest. Это не Apache/MIT; загрузка с Hugging Face не заменяет
проверку права использования. Подробности и ссылка на лицензию —
[D1_MACOS.md](D1_MACOS.md), раздел «Использование в бизнесе».

**Действие:** передать условия ответственному за лицензирование; установить,
какие права нужны для конкретного корпоративного сценария. Если условия не
подходят — получить подходящее разрешение либо выбрать другую модель и заново
проверить качество, протокол вероятностей и память. Не менять модель молча.

**Приёмка:** в документации поставки зафиксированы точная модель, лицензия и
основание допустимого использования. До этого не утверждать, что промышленное
коммерческое применение в МегаФоне уже разрешено.

### MF-02. Claude Code mod: runtime ещё не подтверждён

**Что есть:** `plugins/strategist-routing/hooks/register.mjs`, регистрация через
`hooks/hooks.json`, выбор на `turn.start`, применение model/effort на `turn.step`,
повторная авторизация перед запросом. Node-проверки: 12/12. Ранее штатный
validator принял плагин. Локальный doctor: `configured_not_verified`.

**Наблюдавшийся сбой:** Claude Code 2.1.311, команда `claude plugin test`:

```text
sandbox_apply: Operation not permitted
child exit 71; CLI exit 1; тестовый файл не загрузился
```

На машине разработки использовался корпоративный launcher. Исследование его
кода и контролируемый запуск вложенного процесса без маркера наследования
воспроизвели попытку повторного применения sandbox. Вероятная причина —
очистка окружения дочернего `plugin test`, несовместимая с launcher.
Прямой трассировки env именно Claude test-child не было: это обоснованный
вывод, не подтверждение универсальной ошибки Claude на всех компьютерах.

**Проверить на целевой машине:**

```sh
claude --version
claude plugin validate --strict --json plugins/strategist-routing
claude plugin test plugins/strategist-routing
```

Если повторяется тот же сбой, сохранить версии, точный stderr и код завершения.
Не отключать sandbox, auth или корпоративный launcher для получения зелёного
результата. Исправление совместимости launcher/runner — отдельная область
ответственности; приложению не нужно доверять просто отсутствию env-маркера.

**После устранения блокировки:** запустить новую разрешённую сессию Claude
с плагином, например через `--plugin-dir` по [README мода](../plugins/strategist-routing/README.md).
Дать простую и более сложную задачу; записать решение D1 и модель/effort,
фактически переданные host-ом. Проверить следующее:

- новая задача классифицируется; обычные tool-steps повторно D1 не вызывают;
- следующий ход начинает собственный маршрут, старый не переносится случайно;
- отказ авторизации не вызывает model request;
- недоступная/неуверенная D1 явно сохраняет штатный маршрут без ложного заявления
  об автоматическом переключении;
- обычный subagent маршрутизируется, именованные роли/fork/resume сохраняются.

**Приёмка:** сохранён воспроизводимый native runtime report с версиями,
request/agent ID и фактически использованными model/effort, без секретов.
Node-моки и текст рекомендации D1 сами по себе пункт не закрывают.

### MF-03. Codex app-server блокирует relay на время классификации

**Подтверждено чтением кода:** `tools/codex_routed.py`, функция `relay`,
ветка `turn/start`: синхронный `route_turn(...)` вызывается прямо в selector loop.
Пока D1 отвечает, цикл не читает другие сообщения клиента/сервера.
Это может задерживать interrupt и уведомления; точная задержка в живом UI
в этой итерации не измерена.

**Как воспроизвести без платных моделей:** тестовый `decide` удерживать событием
`threading.Event`, отправить `turn/start`, затем независимое сообщение/interrupt
через fake app-server. Проверить, пересылается ли оно до освобождения `decide`.
Существующая основа: `tests/test_codex_routed.py` и `tools/codex_routed.py`.

**Направление исправления:** вынести классификацию из reader loop, вести
ограниченную таблицу pending по session/thread/request ID. Сверить действующий
протокол interrupt; не придумывать имена методов. При отмене не отправлять
устаревший turn в исполнителя; отменять только соответствующий UUID D1.
Перед реальной отправкой заново проверить конфиг и авторизацию/T4-квоту.

**Приёмка:** reader не блокируется; второй независимый поток обслуживается;
interrupt до/во время/после классификации имеет определённый результат;
нет двойного dispatch, чужих ответов и утечек pending после timeout/EOF.
Тесты на перестановку ответов, повтор ID, отзыв полномочий и завершение child.

**Уже сделано:** `decision_runtime.py` при ошибке соединения/таймауте и
KeyboardInterrupt отправляет best-effort cancel собственного UUID. Это не
полная интеграция host supersession; SIGKILL/неперехваченный SIGTERM не покрыты.
`cancelling` — подтверждение принятого намерения, а не завершённая отмена.

### MF-04. Повторная классификация одного намерения

**Факт:** `tools/hooks/host_prompt.py` классифицирует пользовательский prompt;
`tools/hooks/codex_routing.py` классифицирует текст нового spawn. При
переформулировании текста точный кэш не поможет. При этом spawn может быть
другой подзадачей — автоматически считать его дубликатом нельзя.

**Воспроизведение:** подменить оба `decide` счётчиком; пройти UserPromptSubmit,
затем PreToolUse/spawn_agent с `fork_turns="none"` и переформулированным заданием.
Получатся два вызова. Существующие тесты: `test_host_routing.py`,
`test_codex_routing_hook.py`.

**Направление:** при необходимости добавить проверяемый receipt с привязкой к
конкретной задаче, контексту, версии политики и сроку действия. Решить, кто
имеет право выпускать receipt. Текст промпта, произвольный `model` или номер
сессии сами по себе не являются доказательством согласованного маршрута.

**Приёмка:** одна неизменная подзадача не классифицируется повторно; новая задача,
изменённый контекст, истёкший/чужой receipt и сигнал эскалации требуют нового
решения. Актуальная авторизация и T4-квота проверяются при каждом dispatch.

### MF-05. Claude T4 subagent намеренно запрещён

Это **защитное ограничение**, не случайный сбой. Для первого запроса субагента
ещё не доказаны порядок native events и связь agent ID с маршрутом, необходимые
для надёжного учёта квоты. Основной T4-turn и обычные T1–T3 — отдельные пути.

**Где:** `plugins/strategist-routing/hooks/register.mjs`, README мода и
`tests/routing.node.mjs`.

**Приёмка до снятия запрета:** в реальном runtime доказан учёт именно первого
model request, повторных steps и отказа до запроса при исчерпанной/отозванной
квоте. Fork/resume/custom-role не должны внезапно получать чужую модель.
Не удалять deny лишь ради прохождения демонстрации.

### MF-06. Замеры не равны бизнес-эффекту

Сохранённые в коммите доказательства:

- [Качество D1: 20 кейсов](research/d1-routing-quality-2026-11-15/README.md).
- [Кэш и одинаковые запросы](research/d1-reuse-2026-11-16/README.md).
- [Разные задачи и два native-вопроса](research/d1-overhead-2026-11-16/README.md).

В последнем парном тесте 20 разных задач выполнены в двух вариантах, кэш выключен.
Медиана worker-time 2,15 → 1,76 с, 17/20 совпадений с инженерным эталоном,
те же 8 уверенных решений, 0 ошибок среди этих восьми. Это малая выборка,
не промышленная точность и не гарантия отсутствия ошибок. Слабое покрытие
уверенными решениями не исправлено ускорением. У кэша большой выигрыш был
на специально повторяющихся запросах, не на пяти независимых новых задачах.

**Следующий эксперимент:** четыре режима пользователя — D1, D1+Luna,
Luna, без D1 и без Luna-классификатора. Остальные роли одинаковы; Luna как
исполнитель/верификатор не отключается автоматически в четвёртом режиме.
Использовать одинаковые кейсы и требования качества, разные effort/сложность,
burst и неравномерные поступления, отдельные cold/warm измерения. Зафиксировать
параметры compact_questions/reuse, менять порядок режимов. Калибровку и финальную
проверку вести на разных данных. Порог .75 не считается доказанно оптимальным.

**Приёмка:** raw receipts всех режимов, число пропусков/ошибок, последовательность
model/effort, время очереди и вычисления, токены и расходы исполнителей, retries,
quality review и итоговое качество. Потерянные ответы не удалять из знаменателя.
p95 оценивать на достаточном числе повторов, указав объём и метод; не выводить
его как надёжную характеристику из пяти клиентов. Не публиковать общий ROI
по локальному счётчику input tokens.

### MF-07. Не всё рабочее дерево входит в базовый коммит

На момент передачи вне `e626b5a` оставлены изменения `AGENTS.md`, gate-вопросов,
`skills/claim-verifier`, `skills/validation-plan`, кейса `projects/esim-travel`,
часть исследований, `evals/semantic` и связанные тесты. Это не список удаляемых

нужно проверить отдельно; получить рабочие материалы у автора, если нужен аудит.
На чистом клоне этих незакоммиченных материалов не будет.

**Приёмка:** разделить их на методику, продуктовый кейс и исследования; проверить
каждую группу и оформить отдельными коммитами. Не брать чужие API-ключи,
`routing.local.yaml`, личные пути или веса модели в обычный Git. Для модели
уже есть pinned downloader/revision/SHA256 manifest.

## Что не нужно переделывать без доказанной причины

- Один persistent worker, ограниченная очередь, UUID-проверки, deadlines и отмена.
- Точный RAM-кэш с bounded capacity и обходом для экспериментов.
- Два вопроса native-host и три вопроса обычного delegate; rollback предусмотрен.
- Повторная авторизация при dispatch, allowlist, T4-квота и сохранение специальных ролей.
- Исходные веса, калибровка и проверка их целостности.

Эти механизмы покрыты тестами. Изменение любого из них требует регрессии,
а не повторной реализации похожего механизма рядом.

## Формат сдачи исправления

Для каждого MF-ID оставить: baseline и итоговый commit, краткую причину,
воспроизведение до исправления, точный diff, команды и результаты проверок,
сырые доказательства без секретов, оставшиеся ограничения и способ отката.
Отметить «закрыто» только после соответствующей приёмки выше.
Публикация, подключение новых внешних сервисов и изменение корпоративной защиты
не являются частью этой передачи автоматически.
