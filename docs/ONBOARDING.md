# Первое знакомство и диагностика

Приветствие начинается так:

> Привет! Я Стратег.
>
> Начните обычным сообщением: опишите задачу или приложите файлы — я помогу её
> выполнить либо проведу углублённое исследование на основе ваших материалов.

Дальше — краткое назначение реально присутствующих предметных навыков, способ
маршрутизации в указанной среде и приглашение «покажи навыки» / «проверь и настрой
под мой компьютер». В приветствие не попадают личные глобальные skills разработчика.
Каталог читается из `skills/*/SKILL.md`; сейчас это 14 навыков. `doctor.py skills`
показывает каждому его имя и назначение.

В приветствии также показаны настройка decision-модели и ссылки на Hugging Face:
[исходную D1-2B](https://huggingface.co/LiquidAI/d1-2B) и
[D1-2B MLX 8-bit](https://huggingface.co/LiquidAI/d1-2B-MLX-8bit).
Для macOS с Apple Silicon проверенный путь этой поставки — закреплённая MLX 8-bit.
Если исходные веса не помещаются, выбирайте её. Варианты ниже 8-bit пока не
рекомендуются для поставки: их качество маршрутизации здесь не проверено.
Это не обещание установленной модели: приветствие сохраняет фактический статус
настройки, а инструкция [D1 на macOS](D1_MACOS.md) отдельно описывает установку,
проверку и ограничения. Исходные веса нельзя просто подставить в MLX-сервис.

## Команды

```bash
.venv/bin/python tools/doctor.py welcome --once --host claude-code
.venv/bin/python tools/doctor.py welcome --host codex-app
.venv/bin/python tools/doctor.py skills
.venv/bin/python tools/doctor.py doctor --host cursor
.venv/bin/python tools/doctor.py doctor --host codex-app --json
```

`welcome --once` предлагается через существующий SessionStart; в средах без этого
события агент вызывает его по AGENTS.md. Маркер атомарно создаётся в
`$XDG_STATE_HOME/strategist/welcome-offered-v1.json`, по умолчанию
`~/.local/state/strategist/`. Он общий для пользовательского профиля, не для чата,
продуктового кейса, версии или checkout. Статус `offered` означает передачу гайда
агенту; UI подтверждения фактического прочтения пользователем нет.
Команда без `--once` повторяет гайд и не меняет маркер. Тесты используют временный
профиль и не погашают первое приветствие пользователя.

## Что именно проверяет doctor

Локальный осмотр файлов: предметные навыки, наличие `.venv`, настройки classifier,
регистрация host hooks/мода и включение host_routing. Ни одного inference/API-вызова,
установки, импорта ключей или изменения настроек. Наличие сервиса D1 и его качество
не выводятся из одного YAML; успешные прежние smoke из машины разработчика не
переносятся в статус новой установки.

Для Codex doctor также проверяет executable Python, принадлежность путей текущему
checkout, события/matcher и дубли регистраций. После переноса папки выполните
`tools/install_host_routing.py` для предварительного просмотра и затем `--apply`:
маркированные собственные команды и точные команды старой поставки заменяются,
соседние чужие hooks сохраняются. Неизвестная немаркированная команда из прежней
папки не удаляется автоматически: doctor сообщает `needs_setup`, требуется разбор
её принадлежности. Поставляемый шаблон использует относительные пути; установщик
закрепляет пути новой установки. Это не подтверждение исполнения hook средой.

Статусы:

- `configured_not_verified`: регистрация найдена, но trust/загрузка/исполнение в
  текущей среде не подтверждены.
- `needs_setup`: известный адаптер существует, настройка этой установки неполная.
- `unverified`: среда ещё не проверена (например Cursor); нужен разбор её механизма.

Doctor формирует дальнейшие шаги. Агент по запросу пользователя выполняет доступную
обратимую настройку, затем проверяет сквозной сценарий; новый платный вызов или
передача данных другому провайдеру не разрешаются словом «диагностика».
Отсутствие автороутинга не запрещает продуктовую работу текущей моделью, но об этом
нужно сообщить. Настроить непроверенную среду молча либо объявить её рабочей нельзя.

## Актуальная проверка Codex — 15.11.2026

Установленная CLI 0.169.0 совпадает с последним stable
[релизом от 13 ноября](https://github.com/openai/codex/releases/tag/rust-v0.169.0).
В проверенных официальных контрактах не найден аналог Claude
`turn.step → next({model, effort})`: UserPromptSubmit не меняет основную модель,
PreModelRequest наблюдает, PreToolUse может переписать аргументы spawn, app-server
принимает model/effort на turn/start. Новое изменение effort во время диалога
не является API модов для автоматического выбора модели.

Официальное приложение Codex **поддерживает hooks**. Новые/изменённые project hooks
требуют доверия точному хэшу, иначе пропускаются: Review hooks / Settings → Hooks.
Поэтому наличие конфигурации не означает её исполнение. Наша сквозная интеграция
в отдельном Codex desktop ещё не проверена; локально отдельный Codex.app не найден.
[Hooks и правила доверия](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks),
[app-server](https://learn.chatgpt.com/docs/app-server).

Claude применяет маршрут через наш мод; его native runtime gate остаётся открытым,
как описано в [NATIVE_HOST_ROUTING.md](NATIVE_HOST_ROUTING.md). D1/Jev — выбор маршрута,
mods/hooks/app-server — применение. Это два разных слоя, а не альтернативные технологии.
