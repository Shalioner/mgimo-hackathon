# Автоматический каскад классификаторов

Среда: Codex в Orca. Обновлено 16.11.2026 по явному запросу пользователя.

Порядок фиксирован: **API decision-модель → локальная decision-модель →
подписочная LLM T1/low**. Это выбор классификатора, который затем выбирает
модель и effort для задачи. Исполнитель задачи не меняет аккаунт через этот каскад.
D1 — текущий локальный адаптер, а не название второго уровня или обязательная
модель для архитектуры. Другой локальной модели нужен совместимый адаптер;
замена имени весов не гарантирует совместимость.

## Поведение

- Каждый запрос начинается с API; ошибки, отсутствие/истечение ключа, отказ или
  неуверенность переводят его к следующему уровню. Порог decision-моделей — 0,75.
- Для локального уровня используется существующий сервис и проверка памяти.
  Критическое давление памяти не обходится.
- В Codex/Orca резерв — Luna/low через native app-server текущего аккаунта.
  Перед inference проверяются ChatGPT auth, OpenAI provider и отсутствие стороннего
  endpoint. Инструменты, hooks и делегирование внутри классификатора выключены.
  Ответ — метки с цитатами, порог 0,85; это не калиброванная вероятность LLM.
- В Claude выбирается существующий подписочный adapter Haiku/low с подтверждённым
  dedicated profile. На этом компьютере Claude не авторизован и профиль отключён:
  **третий уровень Claude пока недоступен**. Чужой Codex-аккаунт вместо него не используется.
- Если ни один уровень не дал уверенного ответа, нового маршрута нет. Codex relay
  останавливает запрос; обычные hooks сохраняют маршрут хоста с сообщением.
  Каскад не запускает платную API-модель и не снимает лимиты T4.
- В `classification.attempts` видны `api`, `local-decision`, `subscription`, результат
  и квитанция каждого этапа. `selected_classifier` показывает принятый этап.
  Классификаторы не выполняют исходную задачу.

Общий бюджет времени native helper — 120 с: API ограничен 12 с, локальный этап —
30 с, подписочный получает остаток. Внешний Codex hook ждёт до 130 с.
Низкая уверенность может увеличить время и расход подписочных токенов.

## Классификация инструментов

`tool_router.py`, `route_tools.py` и модельная часть `tool_context.py` используют
тот же порядок API → локальная decision-модель → подписочный T1/low для single-choice
и noul вопросов. Каждый этап выполняется не более одного раза; общий deadline,
разрешение API и отзыв конфигурации сохраняются. Неуверенность запускает следующий
этап: для действия нужен score ≥0,85 и отрыв ≥0,15, для noul — ≤0,1 либо ≥0,9.

Подписочная LLM возвращает метки с дословными цитатами, включая отрицательное noul.
Поля confidence/probabilities/noul в этом случае — **условные оценки политики**,
а не измеренные вероятности. Квитанция содержит
`method: labels_with_quotes_not_calibrated_probabilities`. Цитата проверяет наличие
текста, а не истинность вывода. Отказ всех этапов не запускает инструмент и сохраняет
исходную историю. `attempts` фиксирует этапы, `selected_classifier` — принятый.

Это явные библиотечные/CLI входы: глобальный перехват всех инструментов хоста
не устанавливается. Исполнение остаётся за host с разрешёнными callbacks.

## Настройка

В этом checkout настройки уже внесены в игнорируемый `knowledge/routing.local.yaml`;
предыдущая версия сохранена в `~/.cache/strategist/config-backups/`.
Ключ находится вне репозитория с правами 600. Изменения не включают API в других
проектах и не входят в Git как личная конфигурация.

Основные поля (дополняют существующие allowlist и точный API grant):

```yaml
automatic_routing:
  classifier: cascade
  decision_provider: openrouter
  host_routing:
    api_classifier_opt_in: true
    timeout_seconds: 120
  subscription_classifier:
    enabled: true
    codex_binary: /absolute/path/to/codex
decision:
  providers:
    - name: openrouter
      protocol: openrouter-decisions
      base_url: https://openrouter.ai/api/alpha
      model: perplexity/pplx-decider-v1.3:free
      provider_slug: perplexity
      response_provider: Perplexity
      api_key_file: /absolute/private/path/to/key.txt
execution_policy:
  mode: api_opt_in
  # api.enabled + точный grant с budget_usd: 0 и реальным внешним cap: 0
```

Существующий grant из [OPENROUTER_DECISION.md](OPENROUTER_DECISION.md) обязателен;
одного ключа недостаточно. Нулевой лимит ключа проверяется по API перед каждым
decision-запросом. `subscription_only` не повышается автоматически до `api_opt_in`.
Для отключения внешней классификации верните `classifier: local-d1` и
`api_classifier_opt_in: false`; существующий локальный адаптер останется рабочим.
