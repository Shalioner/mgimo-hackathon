# Локальная D1 для тестирования на macOS

Для этой поставки Стратега на **macOS с Apple Silicon** проверен вариант
[LiquidAI/d1-2B-MLX-8bit](https://huggingface.co/LiquidAI/d1-2B-MLX-8bit).
[Исходная D1-2B](https://huggingface.co/LiquidAI/d1-2B) также доступна на Hugging Face.
Если исходные веса не помещаются в память, выбирайте 8-bit. Наш рабочий MLX-сервис
закреплён именно на 8-bit; исходная версия требует отдельного совместимого runtime
и проверки, а не замены папки весов. Варианты ниже 8-bit пока не рекомендуем для
этой поставки: качество маршрутизации на них не проверено.

Короткие локальные запросы проверены на MacBook Air M1 с 8 ГБ. Это не гарантия
работы при любой нагрузке: память общая с macOS и приложениями, при критическом
давлении сервис возвращает отказ. Intel Mac, Windows и Linux этим MLX-путём
не проверены. Детали измерений: [локальный runtime](LOCAL_DECISION_MLX.md),
[рабочий сервис](D1_SERVICE.md).

не дают. Это конкретная граница поставки, а не заключение о правах организации.

## Использование в других проектах

Оптимизации сервиса не привязаны к eSIM или другому продуктовому кейсу.
Все кейсы внутри одной установки Стратега используют общий runtime и конфигурацию.
Для другой копии Стратега создайте её `.venv`, задайте её собственный
`knowledge/routing.local.yaml`, затем из корня этой копии выполните:

```sh
.venv/bin/python tools/install_host_routing.py
.venv/bin/python tools/install_host_routing.py --apply
.venv/bin/python tools/doctor.py doctor --host codex-app
```

Первый вызов показывает план; второй устанавливает hooks/mod для этой копии,
сохраняя существующие настройки. Doctor не заменяет реальную проверку host.
На том же Mac копии могут обращаться к одному приватному D1-сокету текущего
пользователя: веса и worker не нужно дублировать. Разрешения исполнителей,
allowlist и T4-квота задаются конфигурацией вызывающей копии; сервис решает только
вопросы классификации. Это не изоляция разных пользователей/корпоративных арендаторов.

LaunchAgent закрепляет абсолютный путь к одной установке сервиса. Не удаляйте
и не переносите её, пока она обслуживает другие копии. Не запускайте установку
LaunchAgent поверх него из второго checkout: управление им выполняется из
первоначального checkout. На другом Mac runtime и веса устанавливаются заново
по инструкции ниже; локальные конфиги и доступы автоматически не переносятся.

Произвольный репозиторий без файлов Стратега не получает автороутинг автоматически.
Одних AGENTS.md или работающего D1 недостаточно: нужна отдельная интеграция
host и конфигурации. Глобальная установка во все проекты здесь не выполнена.

## Артефакты модели в репозитории

Вместо многогигабайтных весов репозиторий содержит воспроизводимую ссылку на модель:

- `tools/local_decision_mlx.py`: downloader и закреплённые repo/revision;
- repo: `LiquidAI/d1-2B-MLX-8bit`;
- revision: `3247d0483b11e5da31fa10e7979c23252fbe3580`;
- `tools/local_decision_mlx_manifest.json`: SHA256 каждого файла, включая веса,
  tokenizer, конфигурацию и калибровку;
- `requirements-local-decision-mlx.txt`: закреплённые зависимости;
- файл `LICENSE` модели скачивается вместе с артефактами и проверяется по manifest;
  лицензия модели не заменяется лицензией кода Стратега.

Downloader получает только перечисленные артефакты указанной revision и проверяет
хэши. Веса сохраняются вне Git в
`~/.cache/strategist/d1-2b-lab/mlx-weights/3247d0483b11e5da31fa10e7979c23252fbe3580/`.
При переносе на другой Mac используйте этот же downloader. Не добавляйте веса в
обычный Git и не подменяйте `main` вместо закреплённой revision.

## Установка на новом Mac

Команды выполняются из корня репозитория. Нужен установленный Python 3.12 для
Apple Silicon и основная `.venv` проекта по README. Отдельное окружение для MLX
не меняет зависимости основной `.venv`. Если окружение уже существует, сначала
проверьте его версии; не создавайте заново поверх рабочей установки.

```sh
python3.12 -m venv ~/.cache/strategist/d1-2b-lab/mlx-venv
~/.cache/strategist/d1-2b-lab/mlx-venv/bin/python -m pip install -r requirements-local-decision-mlx.txt
~/.cache/strategist/d1-2b-lab/mlx-venv/bin/python tools/local_decision_mlx.py download
```

Установка зависимостей и `download` используют сеть. Сами запросы D1 затем
выполняются локально, без автоматического перехода на API. Если загрузка прервалась,
downloader сообщает о `.partial`: сначала проверьте этот файл, не удаляйте весь кэш.

Запуск сервиса:

```sh
.venv/bin/python tools/d1_control.py start
.venv/bin/python tools/d1_control.py status
```

`start` устанавливает пользовательский LaunchAgent `local.strategist.d1`, включая
автозапуск при входе. `status` подтверждает сервис, но не качество маршрутизации.
Модель загружается при первом запросе. Настройте `knowledge/routing.local.yaml`
по существующему примеру, сохранив остальные параметры:

```yaml
automatic_routing:
  classifier: local-d1
  local_d1:
    mode: service
```

Путь к приватному сокету определяется для текущего пользователя автоматически.
Затем выполните пробный запрос, где `request.md` — короткое описание вашей задачи:

```sh
.venv/bin/python tools/route_request.py --prompt-file request.md --host codex --classify-only --execute
.venv/bin/python tools/doctor.py doctor --host codex-app
```

Первый вызов запускает только локальную классификацию, не исполнителя. Проверяйте
статус, вероятности и сведения о фактической модели: `needs_review` не означает
принятый маршрут. Doctor не вызывает модель и не подтверждает работоспособность
hook в приложении. Для Claude Code укажите его среду вместо Codex. Применение
выбранной модели требует интеграции host: [границы автороутинга](NATIVE_HOST_ROUTING.md).

```sh
.venv/bin/python tools/d1_control.py stop
```

`stop` останавливает текущий сервис, но не удаляет LaunchAgent. Полный контракт
управления и ограничения памяти — в [D1_SERVICE.md](D1_SERVICE.md).
