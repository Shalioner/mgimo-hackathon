Среда: codex. Пользователь отменил сравнение квантования и уточнил, что нужен
тест качества маршрутизатора. Незавершённая загрузка4bit остановлена; рабочая
8bit D1 и конфигурация не менялись. Полный протокол —
[D1_QUALITY_PROTOCOL](../../../evals/routing/D1_QUALITY_PROTOCOL.md).

tier/effort/capability независимо проверены до inference. Использован только
H.decide → локальный D1. Исполнители, Luna и облачные API не вызывались.

## Что именно ломается

Из12 невыбранных маршрутов9 соответствуют эталону,3 — нет. Ошибки:
Q06 — простая проверка существования файла ошибочно T4 (0.495);
Q07 — бриф ошибочно T1 вместо T2 (0.539);
Q16 — обычная продуктовая стратегия ошибочно T4 вместо T3 (0.483).
Все три остановлены порогом. Среди правильных: Q15 tier=T3 с0.843, но effort
deep с0.506; весь маршрут остановлен. На всех шести T3-кейсах selected отсутствует.

Это не доказывает бесполезность D1. В этом наборе она чаще выбирает ожидаемый
маршрут, чем уверенно разрешает его. Однако низкая уверенность смешивает верные
и неверные предложения; просто отключить gate нельзя. Общий порог0.75 не был
эмпирически настроен на этих задачах и не менялся ради результата.

Старый набор10 разобран отдельно:7 отказов только из-за tier,1 только из-за
effort,2 принятых. Raw разбор: previous-ten-diagnostic.json. Старые кейсы не
добавлены к новым как независимые измерения.

## Время, доказательства, ограничения

Один worker PID43173, generation3. Медиана inference2.099с; очереди4.996с;
client roundtrip7.666с, максимум27.158с. Холодная загрузка14.629с. D1 input8422
tokens, output0 по System One. Платных/API вызовов0; энергия и работа разработки
не измерены. Фоновые условия и сложность отличаются от старого pilot, поэтому
это не доказательство ускорения модели.

Все20 raw receipts пересчитаны: summary совпал точно. Хэши code_snapshot
совпали с manifest. 21 targeted tests passed. Reviewer нашёл риск потери
завершённых receipts в summary при прерывании batch; после frozen run агрегация
переведена на сохранённые файлы и добавлена регрессия. Этот прогон завершился
полностью, результат от исправления не изменился. Рабочие runtime-файлы не правились.

Эталоны инженерные, не человеческая разметка и не замер минимально достаточной
модели. Задачи явно описывают характер работы; один небольшой синтетический
набор не подтверждает общую точность85% и не калибрует вероятности. Ноль ошибок
среди8 принятых не гарантирует нулевой риск на новых данных.

Следующий шаг: отдельные данные для настройки и проверки; оценка ошибки/доли
автоматических маршрутов по порогам; разные правила tier и effort; стоимость
недооценки сложности и перерасхода; Luna-review только неразрешённой части.
При уверенном tier и сомнительном effort проверить политику допустимого
стандартного effort с quality escalation, не вводить её без отдельного теста.
