# D1: повторное использование решений, 2026-11-16

Среда: Codex, MacBook Air M1 8 GiB. Изменены обвязка и инструкции поставки,
не веса, калибровка, порог уверенности или архитектура. Сервис перезапущен без
активных запросов и с пустым кэшем. Один worker на все фазы; сначала отдельный
прогрев. Вызовы локальные, без Luna/исполнителей/платного API.

## Живой замер

Пять конкурентных клиентов в каждой фазе, один прогон. Baseline — `reuse:false`,
кандидат — `reuse:true`. Оба пути через тот же обновлённый сервис. Это A/B отключения
оптимизации, не сравнение двух разных бинарников. Порядок фаз фиксирован.

| Нагрузка | Без reuse, вся группа | С reuse, вся группа | Вызовы D1 без / с |
|---|---:|---:|---:|
| Пять разных новых задач | 11,232 с | 9,458 с | 5 / 5 |
| Пять одинаковых одновременных задач | 8,998 с | 1,658 с | 5 / 1 |
| Повтор пяти уже рассчитанных задач | 9,540 с | 0,012 с | 5 / 0 |

Во всех сравнениях ответы, включая вероятности, совпали точно. Все 30 запросов
получили успешные ответы с собственными ID. При одинаковых запросах группа
завершилась примерно в 5,4 раза быстрее, число вычислений уменьшилось на 80%.
Это эффект специально заданных повторов, не измеренная частота повторов у бизнеса.
Разницу на новых разных задачах не приписываем кэшу: число вычислений то же,
нужны повторные прогоны со сменой порядка для оценки шума.

Сырые ответы, ID, timing и выборки памяти — в JSON каждой фазы. Токены новых
вычислений: одинаковые задачи 1655 → 331; готовые повторы 1896 → 0. Это локальные
input tokens, не денежная экономия API. Метаданные исходного usage сохранены.
Системный swap во время фаз не рос (наблюдаемый диапазон 1780,88–1796,88 MiB).
RSS процесса не отражает всю unified/Metal память; эти выборки нельзя выдавать
за полный расход памяти модели или доказательство отсутствия кратких пиков.

`manifest.json` содержит исходный status, кейсы, вопросы и SHA256 кода.
`benchmark_used.py` — точная версия скрипта прогона. После прогона основной
скрипт дополнен отказом при непустом кэше, чтобы повторный запуск не засчитывал
старые результаты как новые задачи. Для воспроизведения: остановить собственный
сервис без активных задач, запустить и выполнить:

```sh
.venv/bin/python evals/routing/d1_reuse_benchmark.py --output docs/research/<новая-папка>
```

## Проверки и границы

- 99 тестов service/runtime/control/doctor/quality/concurrency прошли вместе.
- После добавления проверки передачи `reuse:false` клиентская группа: 9 passed;
  суммарно покрыто 100 тестов, не все повторялись без необходимости.
- Независимый reviewer воспроизвёл ошибку вытеснения активного ID из истории;
  исправлено резервирование ID по pending и seen, добавлена регрессия.
- Кэш bounded, только RAM, точное совпадение входа, срок пригодности 300 с.
- Отмена/таймаут отдельного ожидающего не разрешают доставку чужого ответа.
- Очередные повторы переиспользуют результат при dequeue, без немедленного fan-out.
- Исторические тесты качества и четырёх режимов теперь отключают reuse, чтобы
  не смешивать эффект классификатора и кэша.

Это проверка локальной обвязки. Она не измеряет итоговую бизнес-пользу,
стоимость исполнителей, качество стратегии или p95 при промышленной нагрузке.
Исходные 20 кейсов качества и четыре экспериментальных режима не заменены этим
тестом. Автоматическое сжатие контекста, приоритеты очереди и изменение выгрузки
модели не включались без отдельных доказательств качества/памяти.
