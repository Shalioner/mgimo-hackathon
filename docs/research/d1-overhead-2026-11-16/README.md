# Разные задачи: накладные расходы и компактный native-роутинг

Среда: Codex, MacBook Air M1 8 GiB, закреплённая D1 MLX 8-bit.
Кэш отключён во всех измерениях. Веса, калибровка и порог .75 не менялись.

## Протокол

20 разных синтетических задач прежнего quality-набора, каждая выполнена дважды:
три вопроса (full) и экспериментальные tier+effort (native_two). Итого 40 запросов
плюс отдельный холодный прогрев. Четыре блока по пять клиентов. В двух блоках
одновременный старт, в двух задержки поступления 0 / .15 / .4 / .8 / 1.4 секунды.
Порядок full/native_two чередуется между блоками. Длина текстов естественная для
набора; предельный контекст и промышленная нагрузка не проверены.

Все 40 ответов succeeded, ID соответствуют отправителям. Это независимые запросы
с отдельным контекстом, но общая предметная область — маршрутизация Стратега.
Они не являются 40 уникальными задачами: 20 задач повторены в двух сравниваемых вариантах.

## Результат

| Метрика | Три вопроса | Два native-вопроса |
|---|---:|---:|
| Совпадение tier+effort с инженерным эталоном | 17/20 | 17/20 |
| Принято при пороге .75 | 8/20 | 8/20 |
| Ошибок среди принятых | 0/8 | 0/8 |
| Входных токенов всего | 8422 | 7142 |
| Медиана worker inference | 2,148 с | 1,760 с |
| Медиана ожидания очереди | 3,995 с | 3,355 с |
| Медиана server total | 6,107 с | 5,038 с |
| Медиана остатка транспорт/обвязка вне setup, queue, worker | 4,03 мс | 3,71 мс |

Все 20 choices tier+effort совпали между вариантами. Уверенно приняты одни и те же
Q01–Q05, Q08, Q19, Q20. Равенство вероятностей не заявляется. Медиана worker-time
уменьшилась примерно на 18%, токены на 15,2%. Это результат малого парного прогона,
а не доказанная универсальная экономия или стоимость результата бизнеса.

У full подготовка в нашей обвязке — median 3,31 мс, проверка/cleanup — 11,90 мс;
вызов system_one с synchronize — 2,134 с. Последний включает внутреннюю подготовку
и постобработку SDK, это не чистое GPU-время. Медианы нельзя складывать для
восстановления медианы total. Отдельная проба sysctl+ps (10 вызовов): median
11,57 мс, max 12,92 мс; защитные проверки памяти сохранены.

Холодный прогрев: setup 12,488 с, полный client roundtrip 14,759 с. Он отделён
от тёплых фаз, не спрятан в среднем. Постоянное удержание модели ради этого
на 8 GiB не включено без отдельной проверки давления памяти.

## Что включено

- Native-host спрашивает tier+effort по умолчанию; исходный текст не сокращается.
  Настройка `host_routing.compact_questions: false` возвращает три вопроса.
  Обычный текстовый delegate сохраняет capability gate.
- UserPromptSubmit пропускает четыре точных acknowledgement без материалов.
  Новые задания, продолжение и вопросы не исключаются.
- При обрыве/таймауте соединения и KeyboardInterrupt клиент делает best-effort
  cancel собственного UUID; чужое подтверждение отклоняет. Повторного inference нет.
- Добавлены измерения preparation / system_one / validation-cleanup и отдельный
  provenance для результата из кэша. Разрешения и T4 quota неизменны.
- Исторические quality/concurrent evals фиксируют старые три вопроса и cache off.

Реальный проход `host_routing.decide` после интеграции сохранён в
`integrated_host.json`: full/all и native/two выбрали тот же маршрут T1;
исполнитель не запускался. Новые tests проверяют переключение, rollback,
отмену через настоящий UNIX socket и дальнейшую работоспособность сервиса.
47 service/reuse tests, 112 host/client/hook tests, затем 18 client/isolation tests;
после compact-интеграции 152 связанных теста прошли. Эти группы пересекаются,
их количества нельзя складывать. Независимый reviewer проверил добавления;
его замечание про проверку ID ответа отмены исправлено и покрыто регрессией.

## Что остаётся отдельной работой

- Prompt → переформулированный spawn может вызвать две классификации. Для
  безопасного переноса решения нужен receipt, связанный с задачей, а не доверие
  полю model или произвольному тексту. Автоматический пропуск не включён.
- App-server relay синхронно ждёт D1. Асинхронная обработка interrupt/supersession
  не реализована в этой итерации. SIGKILL и неперехваченный SIGTERM также не
  гарантируют клиентскую отмену; серверные deadline остаются защитой.
- Нет нового p95, end-to-end расходов агентов или обобщённой оценки бизнеса.
  Неуверенных решений осталось 12/20: ускорение не исправило качество/калибровку.
- Настоящий вычислительный batching не внедрён; приоритеты очереди и смысловое
  сжатие текста не включались без отдельного испытания.

В `manifest.json` — frozen cases, вопросы, исходный status и хэши; в `code/` —
код измерения; каждый raw response записан отдельно. Перезапуск:
`.venv/bin/python evals/routing/d1_overhead_probe.py --output <новая-папка>`.
