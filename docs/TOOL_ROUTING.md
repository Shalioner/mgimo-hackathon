# Выбор инструментов через decision-модель

`tools/tool_router.py` выбирает **одно следующее действие** из списка, подготовленного
host. Модель возвращает ID; команды, аргументы, пути, адреса и разрешения она не создаёт.
CLI выполняет только классификацию. Это библиотечная граница, а не установленный
перехват всех вызовов инструментов Orca.

## Что адаптировано

Собственная реализация использует архитектурный приём
[Semantic Router DecisionRouter](https://github.com/aurelio-labs/semantic-router):
явный вариант отказа и порог уверенности. Исходный код upstream не копировался,
пакет не установлен, новая зависимость не добавлена. Локальный исследовательский
отчёт пока не включён в Git и не является доказательством в публикуемой поставке.

Действие принимается при вероятности от 0.85 и отрыве от следующего варианта от 0.15.
Это консервативная начальная политика проекта, **не доказанная калибровка любой модели**.
`none` означает, что инструмент не требуется или нет обоснованного выбора. Низкая
уверенность, некорректное распределение или отказ транспорта дают `needs_review`.
Без явного classifier/provider возвращается `unavailable`; скрытого fallback нет.

**Открыто:** общий `classifier: cascade` здесь не поддержан; возвращается
`unavailable`. Каскад выбора модели не означает каскад выбора инструментов.
Подробнее: [граница интеграции](CLASSIFIER_CASCADE.md#граница-интеграции-с-инструментами).

## Общий интерфейс моделей

`infer_questions(state, questions, *, execute=False, load_config=..., timeout=240)`
принимает до восьми вопросов System One типов single-choice и `noul` (вероятность yes).
Возвращает `status`, `route`, при успехе `response`. Статусы: `pending`, `succeeded`,
`unavailable`, `needs_review`. Он пригоден и для пакетной оценки релевантности результатов.

Поддержаны существующие маршруты:

- `automatic_routing.classifier: local-d1` — локальный сервис/явная лаборатория через
  `decision_runtime`; исходные ограничения памяти и протокола сохраняются.
- `automatic_routing.classifier: provider` с явным `decision_provider` — настроенный
  `decision.providers` endpoint `/systemone`, локальный или API. Существующая policy
  проверяет разрешение и бюджет. Один API-ключ не даёт права на вызов.

Сервер должен поддерживать **именно контракт System One**, а не только совместимый
chat-completions endpoint. Choice требует probabilities для каждого варианта, сумму 1,
согласованные choice/confidence; noul требует вероятность в [0,1]. Ответы с лишними или
пропущенными ID не принимаются. API может учитывать ненулевые output_tokens; они не
выдаются за нулевую стоимость. Для обычной генеративной LLM адаптер здесь не добавлен.
Новая модель требует отдельной проверки качества на задачах проекта.

## Использование

```bash
.venv/bin/python tools/tool_router.py --request-file request.txt --candidates-file candidates.json
.venv/bin/python tools/tool_router.py --request-file request.txt --candidates-file candidates.json --execute
```

`candidates.json` — от одного до восьми операторских объектов, например:

```json
[
  {"id": "brief", "description": "Прочитать короткую сводку реестра"},
  {"id": "trace", "description": "Проверить основания конкретного решения"}
]
```

Host сам формирует небольшое описание задачи и необходимый контекст; большой исходник
не обрезается молча. `--context-file` добавляет явный контекст. Без `--execute` выполняется
только preflight; с ним — один разрешённый вызов decision-модели, **без вызова инструмента**.

Для исполнения host явно передаёт разрешённые zero-argument callbacks:

```python
report = select_action(request, context, candidates, execute=True)
outcome = execute_selected(report, candidates, {"brief": lambda: read_brief(case)})
```

Host проверяет аргументы и связывает их в замыкании. Он отвечает за полномочия callback;
библиотека не способна определить его побочные эффекты. Список кандидатов привязан к
решению SHA-256. Живой одноразовый ticket защищает от повторного dispatch, в том числе
при параллельном обращении. Ticket потребляется до callback даже при ошибке. Он действует
только в том же Python-процессе, не восстанавливается из JSON после перезапуска и не
заменяет разрешения host. Неиспользованные tickets ограничены 1024, старейший вытесняется.

## Проверено и ограничения

Готовый host-адаптер для реестра:

```bash
.venv/bin/python tools/route_tools.py --request-file request.txt --project projects/example --execute
```

Он выбирает и исполняет один из `brief`, `stats`, `validate`. Путь проекта передаётся
оператором, argv фиксированы кодом, shell не используется. Без `--execute` инструмент
не запускается. Квитанция прежнего локального live-прогона пока не включена в Git;
его результат нельзя воспроизвести по доказательствам в публикуемой поставке.

Сокращение экспортированной истории:

```bash
.venv/bin/python tools/tool_context.py --transcript history.json --goal "Текущая задача" --execute
```

Формат `history.json` — список объектов `role`, `text`, необязательные `tool_calls`
(`id`, `name`, `arguments`) и `tool_results` (`id`, `text`). ID связывает пару; результат
должен идти после вызова. `protected: true` на любой стороне закрепляет пару; `is_error`
на результате сохраняет ошибку. Все цитируемые/используемые реестром результаты
вызывающая сторона обязана закрепить. Оригинальный файл не изменяется, новый вид
возвращается в stdout. Поддержка необработанного формата экспорта конкретного host-а
не подразумевается: его adapter приводит историю к этой схеме.

Текст сообщений остаётся дословным. Первый и последние шесть сообщений сохраняются;
на короткой истории (<16000 байт) D1 не вызывается. До двух последовательных запросов,
по четыре пары в каждом; при сбое возвращается исходный контекст. `stats` содержит
байты до/после и число запросов, receipts — decision probabilities и доступный usage.
Это **не оценка экономии токенов**. Живой D1 также проверен на явно синтетическом
примере устаревшего списка файлов: пара удалена, весь текст сообщений сохранён.

Тесты проверяют preflight без inference, локальный и API-контракты на doubles, отказ,
неуверенность, повреждённые ответы, несовпадение модели, смену конфигурации, привязку
кандидатов, разрешённый callback и защиту от повторного/параллельного выполнения.
Сценарий выбора завершён фактическим вызовом T0 callback, считающего записи.
Это не доказывает точность классификации на живой модели, экономию токенов или
совместимость конкретного стороннего API; такие результаты фиксируются отдельно.
