# Workflow: пересмотр при новых данных

Когда применять: пользователь принёс новый материал; изменился файл источника (`validate` сообщает о несовпадении sha256); сработал триггер пересмотра из DEC; прошёл срок `review_by`.

1. **Зарегистрировать новые сведения.** `ledger.py add-source …` → извлечь новые CLM (навык `source-intake`). Если файл старого источника изменился, зарегистрировать новую версию как новый SRC, а старый пометить `superseded`.
2. **Описать воздействие.** Создать CHG в `changes.yaml`: какой источник и на какие существующие CLM/HYP он влияет (`weakens` / `strengthens` / `contradicts` / `retracts`) и почему. Связь между новым и старым утверждением записать в `contradicted_by`.
3. **Найти затронутое.** `python tools/ledger.py impact projects/<case> CHG-NNN`. Это детерминированный список с путями. **Пересматривается только он.**
4. **Обновить по слоям снизу вверх:**
   - CLM/HYP — пересмотреть `confidence`; если меняется **формулировка** — новый объект + `ledger.py supersede <старый> --by <новый>`, не правка на месте; опровергнутое пометить `retracted`;
   - ALT — пересчитать `scores` и проверить, изменилось ли ранжирование;
   - DEC — перевести в `state: needs_review`, записать в `rationale`, что изменилось;
   - PRM/EXP — проверить, остаются ли обещания и эксперименты верными.
5. **Показать человеку diff решения:** было → стало по каждому затронутому объекту и цепочка `новый источник → утверждение → гипотеза → вариант → решение`. Выбор после пересмотра снова делает человек (checkpoint C2).
6. **Переписать устаревшие места на месте — дешёвой моделью.** Блок «пересмотрено по CHG-NNN» вверху документа — только краткая сводка, а не замена правки. Запусти `python tools/revise_lines.py projects/<case> --change CHG-NNN --step N`. Он найдёт необновлённые строки, отдаст их модели T2 вместе с актуальными формулировками объектов (без целых документов), применит правки и перепроверит. Тебе остаётся просмотреть `git diff -- projects/<case>/outputs` и исправить остаток из его вывода. **Не перечитывай документы целиком при пересмотре** — это главная статья расходов (замер: 38 ходов по ~100K токенов). Если делегировать некому (код 3) — вручную по списку `python tools/verify.py projects/<case> --change CHG-NNN`: он перечислит строки, которые ссылаются на объекты, изменённые по событию по существу, но сами не обновлены. Для каждой строки: если вывод изменился — перепиши её в тексте (было «HYP-003 усиливается» → стало «HYP-003 открыта, версия "достаточно экрана" ослаблена [CLM-025]») и добавь «(пересмотрено по CHG-NNN)»; если не изменился — добавь «(проверено по CHG-NNN)». Пересмотр не закончен, пока список не пуст.
7. **Закрыть событие:** `processed: true` в CHG, запись в `08_decision_log.md` и `run_log.md`, `validate` = 0 ошибок.

Незатронутые артефакты не переписываются. Если пересмотр меняет рекомендацию, обновляются только затронутые разделы стратегий, и в каждом из них есть пометка «пересмотрено по CHG-NNN».
