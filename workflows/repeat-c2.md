# Пересмотр согласованного решения

Цель первого сообщения после нового отчёта — дать руководителю основания и ближайшее действие. Стратегии обновляются после его выбора. До него пакет C3 хранится целиком.

1. Прочитай вход пользователя и вызови `.venv/bin/python tools/review.py context projects/<case>`. Команда показывает прежний выбор, варианты, основания и условия пересмотра. Если нужно, читай конкретное место старого источника. Без квитанции C3, для нескольких решений или при прежней рекомендации применяй [общий пересмотр](update-decision.md).
2. Сопоставь когорту, период, знаменатель и пороги. Зарегистрируй основания командой `.venv/bin/python tools/ledger.py add-source projects/<case> <файл> --title "<название>" --kind document --access own --notes "<границы материала>"`. Для таблицы укажи `--kind table`. Запиши новые CLM и CHG одной пачкой через `yaml.safe_dump(..., allow_unicode=True, sort_keys=False)` и проверь реестр `ledger.py validate`. До C2 оставь старые CLM, ALT, PRM, EXP и согласованные документы без правок.
3. Подготовь краткую записку: что поменялось относительно порогов (с CLM), какое действие сейчас безопасно, какой вариант рекомендуешь, его сильнейший компромисс и что должен выбрать руководитель. Открой C2 одной командой `.venv/bin/python tools/review.py open projects/<case> CHG-NNN --recommend ALT-NNN --basis CLM-NNN [CLM-NNN ...] --memo <файл>`. Команда проверит связи, сохранит точную версию C3 и запишет предложение отдельно от выбора человека. При ошибке разбери указанную причину или используй общий процесс.
4. `.venv/bin/python tools/next.py projects/<case> --resume` выводит вопрос C2, записку и требование приостановить работы. Приведи это в ответе, сохрани действие через `ledger.py log` и дождись выбора. В новом чате начни с той же команды. Если руководитель смотрит HTML, обнови его `report.py` для показа паузы.

После ответа на C2 зафиксируй выбор и актуализируй связи CLM/HYP, варианты, обе стратегии, PRM/EXP и проверку только по затронутым основаниям. Строки, пересмотренные по событию, отмечай с его ID. Выполни `verify.py --strict --change CHG-NNN` и `c3_approval.py prepare` по [общему процессу](update-decision.md). Если выбран другой вариант, CLI требует обновить обе стратегии. Возобновляй работы только в объёме, явно утверждённом руководителем.

### Формат двух записей

`claims.yaml` и `changes.yaml` — списки словарей. Прочитай их существующие ID, чтобы выбрать свободные.

Если аудит прислал письмо и исправленную таблицу, в `CHG.source` укажи файл, который подтверждает новое основание. Если событие привязано к письму, включи в записку хотя бы один CLM с цитатой из письма. В CSV указывай локатор строки и поля; для числового факта можно процитировать точные значения из отдельных полей.

Пример содержит один новый факт и событие.

```yaml
# claims.yaml
- id: CLM-019
  type: fact
  statement: "В этой группе завершили настройку 81 из 120 пользователей."
  confidence:
    level: high
    rationale: "Сумма приведена в исправленной выгрузке."
  evidence:
    - source: SRC-004
      locator: "строка 4"
      quote: "81 из 120"
# changes.yaml
- id: CHG-001
  date: "2026-11-22"
  source: SRC-004
  summary: "Исправлены значения по той же группе и периоду."
  effects:
    - target: CLM-010
      effect: contradicts
      note: "Обновился подсчёт завершённых настроек."
  processed: false
```
