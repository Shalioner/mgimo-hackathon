# Гайды вендоров: когда какая модель эффективна и как её промптить

Сжатые правила из **официальных** руководств: Anthropic, OpenAI, Google, Meta, DeepSeek, Qwen, Kimi, Z.ai GLM, Cursor. Каждый файл — шапка (дата проверки, источники, какие модели покрывает, подсказки для делегирования) и 5–8 правил «что применяем в Стратеге». Пересказ, а не копия: формулировки вендора — в источниках по ссылкам.

## Где вендоры сходятся (это и есть наши общие правила)

| Правило | Кто говорит | Где у нас |
|---|---|---|
| Начинать с дешёвого, повышать только при доказанном разрыве | Anthropic, OpenAI (reasoning планирует, GPT исполняет) | уровни T0–T4, эскалация на одну ступень |
| **Сначала глубина рассуждения (effort), потом модель** | Anthropic; у OpenAI, DeepSeek, Kimi, GLM — `reasoning_effort` | эскалация: тот же уровень с большим effort → следующий уровень |
| Не просить «думай пошагово» у рассуждающих моделей | OpenAI, Google | промпты делегата и субагентов — только задача и формат |
| Детерминированное — инструментам, суждения — модели | Kimi, Meta, Google (код для арифметики) | T0: ledger.py, verify.py, Python для таблиц |
| Длинные данные в начале, инструкция в конце; разделители | Anthropic, Google, Kimi | `delegate.py`: данные в блоках ДАННЫЕ, задача отдельно |
| Разрешить «не знаю» вместо выдумки | Meta, Kimi | правило пробелов в AGENTS.md §3 |
| Схема вместо описания формата в тексте | Kimi, Google (structured output) | schemas/ledger.schema.json + validate |
| Сессия на задачу, длинное — суммировать, план до действий | GLM, Cursor | progress.md, checkpoints, новый чат «продолжи» |
| Противоречивые инструкции стоят токенов | OpenAI | AGENTS.md ревьюится по итогам E2E |

## Важные особенности моделей (легко ошибиться)
- **GLM-5.3**: рассуждение не отключается, `reasoning_effort` по умолчанию `max` — для лёгких задач явно `low`.
- **Kimi K3**: всегда рассуждает, effort по умолчанию `max`, менять до начала диалога.
- **DeepSeek** с инструментами: возвращать `reasoning_content` всех ходов, иначе 400.
- **Qwen3** в режиме мышления: не использовать жадное декодирование; высокий presence_penalty смешивает языки.
- **Claude**: `budget_tokens` на новых моделях — ошибка, ограничивать через effort.

## Как это обновляется само

1. **Модели.** В `knowledge/routing.yaml` для семейств, где это возможно, указан не ID, а шаблон (`gpt-*-sol`) и запасной ID. `python tools/models.py scan` собирает, какие модели реально доступны на машине (кэш Codex, `opencode models`, конфиг ZCode), а маршрутизация берёт **самую новую версию по шаблону**. Вышла `gpt-6.2-sol` — она подхватится без правки файлов; не доступна — используется запасной ID.
2. **Проверка при старте.** Хук SessionStart запускает `models.py check`: он сообщает о новых версиях и о гайдах, которые устарели (старше `refresh_after_days`) или не покрывают появившуюся модель (её нет в `covers`).
3. **Обновление гайда** — задача агента по навыку `skills/model-refresh`: перечитать официальные источники, обновить правила, `checked`, `covers` и `delegate_hints`. Подсказки из `delegate_hints` автоматически добавляются в задания `tools/delegate.py` для этого семейства — так вместе с моделью обновляется и промпт.
4. Запасные ID в `routing.yaml` обновляет `models.py apply` (по команде человека или разработчика, с записью в журнал).
